## Findings

### 🔴 Critical
1. [§3.4 L433-L463; L395-L402] — `subscribe -> Stream<PostAckFrame>` cannot carry the required initial `SubscribeAck`.
   **Fix:**
   `### 3.4 subscribe(channel, since_fingerprint, since_stream_seq, since_boot_id) → Stream<SubscribeFrame>`

   `where SubscribeFrame := SubscribeAck | PostAckFrame. The first frame on every stream is exactly one SubscribeAck; all subsequent frames are PostAckFrame values. SubscribeAck MUST NOT appear after the first frame; PostAckFrame::ReplayCancelled, when emitted, MUST be the last frame.`

2. [§3.4 L742-L743; L953-L963; T-29 L2195-L2203] — clause (c) text conflicts with the closure rule and clause-independence/testing language.
   **Fix:**
   `Any subscribe carrying since_fingerprint = None is routed by closure precedence to clause (c) only when no higher-priority force-resync clause fires; per the closure rule, (a) and (P) take precedence on attribution. Outcome is identical (Resync) in all such cases; only the attributed clause differs.`

   `The daemon MUST evaluate the truth of all six predicates (a),(P),(b),(c),(d),(d′) from the same coherent state observation before choosing an ack. Multiple predicates MAY evaluate true for a single subscription tuple. The daemon MUST emit exactly one ack by selecting the highest-precedence true predicate in the order (a) > (P) > (b) > (c) > (d) > (d′). Clause (c) does not short-circuit evaluation; it only guarantees that the selected wire outcome is Resync whenever (c) is the highest-precedence true predicate.`

3. [§3.4 L699-L703; T-10-pre-v1 L2233-L2243; T-30b-pre-v1 L2245-L2252] — pre-v1 says clauses (d)/(d′) MAY fire, but tests require they do fire.
   **Fix:**
   `Clauses (d) and (d′) MUST fire if s_c is in-window and the fingerprint predicate resolves per their normal triggers; the daemon MUST treat since_boot_id == None as boot-match-assumed for same-boot evaluation. Tests T-10-pre-v1 and T-30b-pre-v1 cover these cases.`

4. [§3.4 L906-L913] — Z-29 boot-edge claims clauses (d)/(d′) can fire with an empty replay index; that contradicts the clause triggers and index lookup rules.
   **Fix:**
   `Boot edge (current_stream_seq == 0). The replay index and delta payload buffer MAY both be empty. In this state ring_oldest_seq is undefined, clauses (d) and (d′) MUST NOT rely on replay-index membership, and outcomes reduce to: (1) if since_stream_seq == Some(0), boot matches (or is assumed for pre-v1), and since_fingerprint == current_fingerprint, emit vacuous UpToDate { stream_seq: 0 }; (2) otherwise emit Resync { snapshot, stream_seq: 0 }.`

### 🟡 Important
1. [§3.4 L404-L408; L852-L857; T-31 L2254-L2271] — `BufferEviction` and `LockStepTrimRace` are on the wire but have no trigger semantics or tests.
   **Fix:**
   `### T-31a: ReplayCancelled on payload-buffer eviction`

   `Subscriber attaches in clause (d) replay mode. Fault-inject eviction of a required replay frame from the delta payload buffer while the replay-index entry still exists. Expected: daemon emits exactly one PostAckFrame::ReplayCancelled { reason: ReplayCancelReason::BufferEviction, .. }, then closes the stream; subscriber re-subscribes with since_fingerprint = None and receives Resync via clause (c).`

   `### T-31b: ReplayCancelled on lock-step trim race`

   `Subscriber attaches in clause (d) replay mode. Fault-inject a non-atomic trim so the replay index and delta payload buffer disagree for one required stream_seq. Expected: daemon emits exactly one PostAckFrame::ReplayCancelled { reason: ReplayCancelReason::LockStepTrimRace, .. }, then closes the stream; no further post-ack frames are written.`

2. [§3.4 L855-L863] — `ReplayCancelled.stream_seq` semantics are unspecified.
   **Fix:**
   `The stream_seq field on ReplayCancelled carries current_stream_seq as observed by the daemon at cancel time. It is diagnostic-only: subscribers MUST NOT use it to construct the follow-up subscribe; the follow-up MUST carry since_fingerprint = None and route through clause (c).`

3. [§3.4 L714-L729; §3.4.1 L1024-L1026, L1044-L1048] — “pre-v1” is ambiguous: the real discriminator is `since_boot_id = None`, not caller generation.
   **Fix:**
   `Definition: pre-v1 vs v1+ subscribe envelopes (normative). The subscribe envelope carries no explicit version discriminator. For the purposes of this section, an envelope is classified as pre-v1 iff since_boot_id == None, and v1+ iff since_boot_id == Some(_). The classification is per-envelope, not per-caller.`

4. [§3.4 L596-L605] — vacuous `UpToDate` remains easy to misread as a fingerprint-equality shortcut; the intended nonzero-gap exclusion should be stated more directly.
   **Fix:**
   `Vacuous UpToDate fires iff s_c == current_stream_seq, boot_id matches (or is assumed per pre-v1), and none of (a),(b),(c),(d),(d′),(P) fires. Any nonzero gap (s_c < current_stream_seq) with fp_at(s_c) == last_known_fingerprint routes to clause (d) — including the case where last_known_fingerprint == current_fingerprint because the gap contains only fingerprint-excluded deltas.`
