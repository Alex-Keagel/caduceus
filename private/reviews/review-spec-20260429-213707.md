## Findings

### 🔴 Critical
1. [docs/specs/spec-caduceus-orchestrator-algorithm.md:880-906] — `on_retry_timer`'s `TrackerClass::Terminal` arm still drains state without writing `recent_history_ring`. The claim at 892-895 that an earlier §3.2/§3.4 cascade site already wrote the entry is not satisfiable for retry-pending runs because those sites iterate `state.running`, and `on_worker_exit` removed the run from `state.running` at 707-779. **Fix:** Replace the 880-906 block so the retry-fire `Terminal` arm is itself the canonical finalize site and MUST emit exactly one ring entry before draining maps.
2. [docs/specs/spec-caduceus-orchestrator-algorithm.md:1383-1387, 1418-1426] — Ring invariant prose still excludes retry-timer finalize paths, so the spec architecture still has no normative writer for retry-fire `Terminal`/`Neither`. **Fix:** Expand the writer-set and invariant text to include a retry-fire finalize helper or equivalent normative write path.

### 🟡 Important
1. [docs/specs/spec-caduceus-orchestrator-algorithm.md:352-369] — Helper postconditions overclaim closure by citing drain sites, but draining tokens is not equivalent to guaranteeing a cascade summary write. **Fix:** Narrow the claim to token-drain closure and explicitly require retry-fire `Terminal`/`Neither` to route through a finalize path that writes the ring.
2. [docs/specs/spec-caduceus-orchestrator-algorithm.md:908-911] — The `Neither` arm claims symmetry with `terminate_and_finish` early-return, but on retry-fire there may be no earlier writer. **Fix:** Specify whether retry-fire `Neither` must also emit a ring summary or justify why it is intentionally non-terminal and excluded.
3. [docs/specs/spec-caduceus-orchestrator-algorithm.md:782-786] — `push_finished` docstring still defines too narrow a caller set for the guarantees claimed elsewhere. **Fix:** State that any retry-fire finalize path must reach the same writer or an equivalent helper.

### 🟢 Suggestions
1. [docs/specs/spec-caduceus-orchestrator-algorithm.md:2405-2409] — Replay-ring vs `recent_history_ring` separation is clear and appears closed.
2. [docs/specs/spec-caduceus-orchestrator-algorithm.md:971-1003] — Defer-abandon drain rationale is coherent as a non-terminal cleanup path, but it should not be used as precedent for retry-fire `Terminal`.

## Recommended Actions
1. Make retry-fire `TrackerClass::Terminal` a normative ring-writing finalize path.
2. Decide explicitly whether retry-fire `TrackerClass::Neither` is terminal-for-history purposes; document and enforce the same answer everywhere.
3. Update ring invariant / helper-postcondition text so writer-set, drain-set, and cascade-set all match.
