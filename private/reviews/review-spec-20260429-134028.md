## Findings

### 🔴 Critical
1. [docs/specs/spec-caduceus-agent-runner-contract.md:712-794, 949, 366-372] — `handshake` is specified as an inbound queue frame that MUST NOT be dropped under saturation, but the §3.2 algorithm consumes it locally and `continue`s without forwarding it to daemon consumers. The spec currently gives two incompatible implementations. **Fix:** Either (a) amend §3.2 so a validated handshake is wrapped and forwarded through the same inbound queue path as other agent→daemon frames, or (b) remove `handshake` from the §3.5.1 queue membership and from the §4.1 agent→daemon kinds table, and state explicitly that handshake is runner-local and only reflected as daemon-internal `handshake_ok` observability.
2. [docs/specs/spec-caduceus-agent-runner-contract.md:1395-1403, 1336-1339] — Daemon-side reattach rule 1 says any `supplied_runner_seq <= daemon_high_water` returns `Ok`, which leaves no normative path for `ReattachWindowExpired` when the requested cursor is older than `oldest_buffered_seq`. **Fix:** Split rule 1 so `Ok` applies only when `oldest_buffered_seq <= supplied_runner_seq <= daemon_high_water`; add a preceding rule that if `supplied_runner_seq < oldest_buffered_seq`, the daemon MUST return `Err(ReattachWindowExpired { oldest_buffered_seq, daemon_high_water })`.
3. [docs/specs/spec-caduceus-agent-runner-contract.md:517-526, 833-839] — §3.3 Stage 1 says outbound-control enqueue failure during `stop_cascade` emits `stage1_cancel_skipped` and falls through, while §3.5.2 says any outbound Control enqueue failure within `GraceWindow` MUST emit `outbound_backpressure` and trigger `stop_cascade`. Without an explicit carve-out, the spec is re-entrant and contradictory on the same failure mode. **Fix:** Add an explicit exception in §3.5.2 or §3.3 stating that Stage-1 cancel enqueues originating inside `stop_cascade` use Z-26’s `ε₁` budget and `stage1_cancel_skipped` fall-through semantics instead of the general `outbound_backpressure` rule.

### 🟡 Important
1. [docs/specs/spec-caduceus-agent-runner-contract.md:1698, 1786] — T-1/T-9 use `≤ ... ± measurement jitter` without a bounded tolerance, so the conformance test is not objectively pass/fail. **Fix:** Replace with an explicit tolerance budget (for example, `≤ 2250 ms + 200 ms CI tolerance`) or define `measurement_jitter_ms` normatively in §5.

### 🟢 Suggestions
1. [docs/specs/spec-caduceus-agent-runner-contract.md:1417-1419, 1757-1759] — “same response shape” for duplicate reattach `Ok` responses is easy to over-read as field-equality even though `current_runner_seq` may legitimately advance between duplicates. **Fix:** Say “same response variant; mutable fields like `current_runner_seq` reflect current high-water and replay dedup remains by `runner_seq`.”

## Recommended Actions
1. Resolve the handshake-path contradiction by choosing a single normative flow and updating both §3.2 and the queue/message tables to match.
2. Fix the daemon-side reattach decision tree so `ReattachWindowExpired` is reachable and testable.
3. Add a stop-cascade carve-out for Stage-1 outbound enqueue failure versus the general outbound-backpressure rule.
4. Bound timing-test jitter so T-1/T-9 are mechanically enforceable.
