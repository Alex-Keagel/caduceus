## Core verdict

B21 does **not** fully resolve C20. In the retry-pending path, `on_worker_exit` removes the `RunningEntry` and schedules `Cmd::RetryRun`, but `reconcile_running_runs` only inspects `state.running`, so no upstream §3.1 / §3.2 / §3.4 path can guarantee a prior `recent_history_ring` write before `on_retry_timer` classifies the run as `Terminal` or `Neither`. The new B21 `on_retry_timer` arms drain maps but still permit **no-ring-write** finalization.

### Control-flow trace

1. `on_worker_exit` removes `state.running[run_id]` (`L708-L711`).
2. For `Normal` / `Abnormal`, it inserts `RetryEntry` and schedules `Cmd::RetryRun` (`L767-L779`); it does **not** call `push_finished`.
3. `reconcile_running_runs` builds its sweep exclusively from `state.running` (`L432-L452`, `L500-L509`), so the retry-pending run is invisible to stall sweep, WorkSource refresh, and orphan reaper.
4. `on_retry_timer` later classifies the run as `Terminal` or `Neither` (`L880-L923`) and drains state without a ring write.

## Exact replacement text for sub-8 scores

### Replacement block A — Correctness / Completeness

```text
Retry-pending terminalization (normative). A run that has exited through
`on_worker_exit`'s `Normal` or `Abnormal` arm is no longer present in
`state.running`, but it remains logically live via `RetryEntry` until the
scheduled `Cmd::RetryRun` is resolved. Because `reconcile_running_runs`
(§3.2) inspects only `state.running`, it cannot guarantee a prior
`recent_history_ring` write for such a run. Therefore, if `on_retry_timer`
is the first handler to observe that retry-pending run as `Terminal`,
`Neither`, or absent from `WorkSource`, `on_retry_timer` MUST perform the
canonical finalize for that run before draining `claimed`,
`retry_attempts`, `dispatch_defer_attempts`, `token_totals`, and
`last_reported_tokens`. This finalize MUST append exactly one
`FinishedRunSummary` whose `exit_reason` is `ExitReason::DaemonTerminated`
with cause `WorkSourceTerminal`, `WorkSourceLeftQuery`, or
`WorkSourceMissing` respectively. The retry-pending finalize path MUST carry
forward enough state from the prior `RunningEntry` (at minimum: `run_id`,
`repo_coordinate`, `attempt`, `restart_count`, and `started_at`) to
synthesize that summary after `on_worker_exit` has consumed the live
`RunningEntry`.
```

### Replacement block B — Architecture / ring wording

```text
Ring invariant #1 (single writer, normative). Only the daemon's main task
writes to `recent_history_ring` (I-1). The only normative writer sites are:
(a) `terminate_and_finish`, which finalizes daemon-driven cascades while a
live `RunningEntry` is still present; (b) the defensive
`ExitReason::DaemonTerminated` arm in `on_worker_exit`; and (c) the
retry-pending finalize path in `on_retry_timer`, used when `on_worker_exit`
has already consumed the `RunningEntry` but `on_retry_timer` becomes the
first terminal observer for that run. No worker task, RPC handler, or other
retry branch may append to the ring.

FinishedRunSummary lifecycle (normative). Exactly one
`FinishedRunSummary` MUST be appended for every terminal outcome of a run.
A non-terminal `Normal` / `Abnormal` exit that schedules retry does not write
its summary at `on_worker_exit`; however, if that retry-pending run later
becomes `Terminal`, `Neither`, or absent from `WorkSource` before a fresh
spawn occurs, `on_retry_timer` MUST append the canonical summary for that
terminal outcome.
```

### Replacement block C — Clarity

```text
The terminal cascade ring entry is written by whichever §3.2 cascade call
site first observes the run while it is still present in `state.running`.
That guarantee does not apply to retry-pending runs: once `on_worker_exit`
has removed the `RunningEntry`, the §3.2 cascade sites cannot see that run.
In that retry-pending case, `on_retry_timer` is the first terminal observer
and MUST write the canonical `FinishedRunSummary` before draining maps.
```

### Replacement block D — SRP / KISS-DRY

```text
The drain sites are: `terminate_and_finish`, the `runs.is_empty()` branch in
`on_retry_timer`, the dispatch-defer abandon branch in `on_retry_timer`, the
defensive `DaemonTerminated` arm in `on_worker_exit`, and the
`TrackerClass::{Terminal, Neither}` branches in `on_retry_timer`. These
sites do not all remove the run from `state.running`: the retry-pending
cleanup branches run after `on_worker_exit` has already consumed the live
`RunningEntry`. The common invariant is not "each branch removes from
running"; it is "each branch drains every per-run map it still owns, and any
branch that is the first terminal observer MUST append exactly one
`FinishedRunSummary` before draining token maps."
```

## Recommended Actions

1. Treat B21 as **partial**, not complete; the no-ring-write gap still exists.
2. Preserve a finalize snapshot across the retry window and make `on_retry_timer` the canonical writer when it becomes the first terminal observer.
3. Replace stale section / line references with stable function / section references.
4. Add a direct test for retry-pending `Terminal` / `Neither` / missing-row finalization.
