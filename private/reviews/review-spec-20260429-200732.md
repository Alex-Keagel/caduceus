## Findings

### 🔴 Critical
1. [spec-orchestrator-status-snapshot.md:525-545, 675-683] — Clause (d) is gated on `last_known_fingerprint ≠ current_fingerprint`, so if a subscriber missed only fingerprint-excluded changes (e.g. token-only deltas) and reconnects with `s_c < current_stream_seq` but matching current fingerprint, the daemon emits vacuous `UpToDate` and advances the cursor without replaying the missed deltas. Concrete counterexample: subscriber at `s_c=9`; daemon has emitted token-only deltas 10 and 11; fingerprint is unchanged; ack jumps cursor to 11 and the subscriber is now permanently stale on excluded fields. **Fix:** replace lines 525-545 and 675-683 with:

```text
- `subscribe(channel, since_fingerprint = Some(_), since_stream_seq = Some(s_c), since_boot_id)`
  where `since_fingerprint` matches the daemon's current fingerprint,
  `s_c == current_stream_seq`, `boot_id` is unchanged, and no
  force-resync clause fires
  ⇒ **vacuous `UpToDate`**: subscriber retains its local snapshot;
  `ack.stream_seq = current_stream_seq`; no replay is performed.

- `subscribe(channel, since_fingerprint = Some(_), since_stream_seq = Some(s_c), since_boot_id = Some(daemon.boot_id))`
  where `s_c` is in-window (clause (a) does not fire) AND
  `last_known_fingerprint == daemon.fingerprint_at(s_c)` AND
  `s_c < current_stream_seq`
  ⇒ **clause-(d) `UpToDate { stream_seq: s_c }` + post-ack delta
  replay `(s_c, current]`**: subscriber retains its local snapshot at
  `s_c`, applies the buffered deltas in strict ascending `stream_seq`
  order to advance to `current_stream_seq`, then resumes live deltas.
  Equality or inequality between `last_known_fingerprint` and
  `daemon.current_fingerprint` is irrelevant: if any replayable gap
  exists after a historically consistent cursor, the daemon MUST replay
  it so fingerprint-excluded fields also converge.
```

```text
- *Trigger.* Subscriber's `since_boot_id` matches the daemon's
  `boot_id`, `since_stream_seq = Some(s_c)` is within the
  `recent_history_ring` window (i.e., clause (a) does NOT fire),
  `last_known_fingerprint == daemon.fingerprint_at(s_c)` (the
  subscriber's view at `s_c` was historically consistent), AND
  `s_c < current_stream_seq`. This is the canonical
  "subscriber missed one or more deltas" case, including gaps that
  changed only fingerprint-excluded fields.
```

2. [spec-orchestrator-status-snapshot.md:745-749] — Replay-mode fallback emits `Resync` after the initial `SubscribeAck`, but §3.4 says the stream is `SubscribeAck` followed by `SnapshotDelta` only, and §3.4 closure says exactly one ack per subscribe. Mid-stream `Resync` is therefore illegal. **Fix:** replace lines 731-750 with:

```text
**Replay-mode subscriber buffering (normative).** When the daemon
serves clause (d), it MUST first pin the exact replay set
`(s_c, current_stream_seq_at_ack]` for that subscriber before writing
the initial `SubscribeAck`. While in replay mode:

1. The daemon emits `UpToDate { …, stream_seq: s_c }` first.
2. Then it emits each pinned delta in
   `(s_c, current_stream_seq_at_ack]` in strict ascending `stream_seq`
   order.
3. Any live delta with `stream_seq > current_stream_seq_at_ack`
   produced during this window MUST be buffered per-subscriber and
   released only after step 2 completes.
4. After the initial `SubscribeAck` is written, the stream carries
   only `SnapshotDelta` frames. The daemon MUST NOT emit a second
   `SubscribeAck` or any other mid-stream control frame. If the daemon
   cannot pin the complete replay set before step 1, it MUST choose
   `SubscribeAck::Resync` before writing the first frame.
```

3. [spec-orchestrator-status-snapshot.md:693-705, 770-785] — The replay index / payload retention contract is internally inconsistent. Lines 693-705 retain payloads for `(current - ring_size, current]`, but Z-29 then requires both index and payload buffer to contain `[ring_oldest_seq, current_stream_seq]`. That makes the anchor sequence both required and forbidden in the payload buffer. **Fix:** replace lines 693-705 and 770-785 with:

```text
**Delta payload buffer (normative).** Distinct from both
`recent_history_ring` (finished-run summaries) and the replay index
(fingerprint map): the daemon MUST retain serialized `SnapshotDelta`
payloads for `stream_seq ∈ (ring_oldest_seq, current_stream_seq]`,
where `ring_oldest_seq := max(0, current_stream_seq -
recent_history_ring_size)`. The replay index MUST retain fingerprints
for `stream_seq ∈ [ring_oldest_seq, current_stream_seq]`. This
one-sequence-number offset is intentional: the replay index includes the
anchor `s_c`, while the payload buffer contains exactly the deltas that
may be replayed after that anchor. If the replay index is missing `s_c`
or the payload buffer is missing any `stream_seq` in `(s_c, current]`,
the daemon MUST emit `Resync`, NOT a partial replay.
```

```text
  1. **Oldest retained sequence.** `ring_oldest_seq = max(0,
     current_stream_seq - recent_history_ring_size)`.
  2. **Dense replay index.** Every `stream_seq ∈ [ring_oldest_seq,
     current_stream_seq]` MUST be present in the replay index.
  3. **Dense payload buffer.** Every `stream_seq ∈ (ring_oldest_seq,
     current_stream_seq]` MUST be present in the delta payload buffer
     (§3.4 above).
  4. **Lock-step trim.** Trim MAY occur only from the oldest end and
     MUST preserve the index/buffer offset above atomically.
```

### 🟡 Important
4. [spec-orchestrator-status-snapshot.md:637-642] — Clause (b) “independence from clause (d)” text describes clause (d) as cursor-divergent (`fingerprint at that cursor disagrees`), which is actually clause (d′). That inversion can make implementers resync when they should replay. **Fix:** replace lines 637-642 with:

```text
- *Independence from clauses (d) and (d′).* Clause (b) is the
  **cross-incarnation** trigger. Clause (d) is **same-boot, in-window,
  cursor-consistent** replay (`fp_subscriber == fp_at(s_c)` and
  `s_c < current_stream_seq`). Clause (d′) is **same-boot, in-window,
  cursor-divergent** resync (`fp_subscriber != fp_at(s_c)`). They are
  disjoint from (b) by `since_boot_id == daemon.boot_id` on (d)/(d′).
```

5. [spec-orchestrator-status-snapshot.md:1996-2003] — T-27 is under-specified and overclaims what it proves. As written it omits `since_stream_seq`, so the §3.4 input-validity rule can route it through clause (c); if `since_stream_seq` is later supplied from a prior boot, clause (a) may co-fire. The test can verify pre-v1 cross-incarnation Resync, but not isolate clause (b) fallback alone. **Fix:** replace lines 1996-2003 with:

```text
### T-27: Pre-v1 cross-incarnation Resync via fp-inequality

Subscriber omits `since_boot_id` (sends `None`), supplies
`since_fingerprint` from a prior daemon incarnation AND
`since_stream_seq = Some(s_prior)` with `s_prior > 0`. After daemon
restart (`stream_seq` reset to 0), assert `SubscribeAck::Resync`.
Verifies that pre-v1 callers reach Resync; the daemon MAY attribute
this to clause (a), clause (b), or both, but it MUST emit exactly one
`Resync` frame on the wire.
```

## Recommended Actions
1. Fix clause (d) so replay is keyed on `s_c < current_stream_seq`, not current-fingerprint inequality.
2. Remove the illegal mid-stream `Resync` path by deciding replay-vs-resync before the first ack frame.
3. Reconcile replay-index vs payload-buffer retention semantics and make the anchor/payload offset explicit.
4. Correct clause (b)/(d)/(d′) independence prose.
5. Repair T-27 so the test asserts the actual pre-v1 guarantee.
