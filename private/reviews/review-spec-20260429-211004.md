## Findings

### 🔴 Critical
1. [1690, 1708-1711, 1813-1832] — Crash recovery for `CleaningUp` is still broken. §5B.1 says `CleaningUp` rows re-enter cleanup, but §5B.2 only classifies `Creating`/`Active` at startup and only re-evaluates `OrphanPending`/`CleanupFailed` in reconcile. A crashed `CleaningUp` row has no guaranteed path back into cleanup.
   **Fix:** Replace the `CleaningUp` action text with: `cleanup_workspace(_, OrphanReclaim, Some(&row))` re-enters §3.6 after the caller has reacquired locks in §4.5 order and re-run §3.6 step 2 path validation; it skips ONLY step 4's layered liveness probe, then runs steps 5/5a/6/7/8/9 unchanged. Also amend §5B.2 step 4 to say: `For every row in Creating, Active, or CleaningUp:` and add `CleaningUp rows MUST be enqueued to OrphanReclaim unconditionally on the first reconcile pass.`

2. [1690, 1817-1819] — The claimed “step 3 not step 4” fix is still wrong/incomplete. The text now says re-enter at step 3 and skip step 4, which silently skips §3.6 step 2 re-validation even though the queue-bypass rule only authorizes skipping the layered liveness probe within step 4.
   **Fix:** `cleanup_workspace(_, OrphanReclaim, Some(&row))` re-enters §3.6 with the caller having already reacquired locks in §4.5 order; it MUST run step 2 and step 3, and at step 4 it skips ONLY the layered liveness probe per the OrphanReclaim-queue bypass. Steps 5/5a/6/7/8/9 run unchanged.`

3. [351-370, 408-417, 638-640, 713-716] — The `CleanupFailed` / `OrphanPending` no-overwrite guard is only partially fixed. Step 1.4 correctly says do not insert/overwrite, but step 9 and step 10c still read as if a placeholder always exists, and step 1.2's “transfers control directly to step 5b” language is ambiguous enough to skip required setup.
   **Fix:** Replace the step 1.4 precondition block with: `step 1.4 inserts a Creating placeholder ONLY when step 1.2 found no matching row. If step 1.2 found Status ∈ {CleanupFailed, OrphanPending}, this invocation MUST NOT create, overwrite, or delete any registry row for that workspace_id. That row is carried forward intact for step 5b's reclaim-deferred routing, and any cleanup of it is owned by reconcile.` Replace step 9's transition sentence with: `If this invocation inserted a placeholder in step 1.4, transition that row from Creating to Active and overwrite path with canonical_target; otherwise this step is unreachable because the CleanupFailed/OrphanPending branch must already have returned from step 5b.` Replace step 10c with: `If step 1.4 inserted a Creating placeholder, remove that placeholder row; otherwise this sub-step is a no-op and the pre-existing CleanupFailed/OrphanPending row MUST remain intact.`

### 🟡 Important
1. [489-503, 1403] — §4.4's `WorkspaceBusyOrReclaiming` text is mostly correct, but §3.5 step 5b still contains live-row / duplicate branches that contradict it. If `Creating|Active|CleaningUp` exists, step 1.2 already returns `WorkspaceBusy`; step 5b should not still model that row source.
   **Fix:** Replace the step 5b decision-table lead-in with: `This table applies only when the pre-step-1.4 registry snapshot shows either no matching row or a matching row with Status ∈ {CleanupFailed, OrphanPending}. Rows with Status ∈ {Creating, Active, CleaningUp} are rejected earlier at step 1.2 as Error::WorkspaceBusy and MUST NOT reach step 5b.`

2. [1992] — T-16 still allows unreachable errors. For a clean same-`(slug, run_id)` race, the loser should see `WorkspaceBusy`; `WorkspaceAlreadyExists` is blocked by step 1.2, and `WorkspaceBusyOrReclaiming` requires pre-existing reclaim-owned state.
   **Fix:** `T-16: Two concurrent create_workspace calls with the same (slug, run_id) on a clean namespace ⇒ exactly one succeeds; the loser returns Error::WorkspaceBusy. Error::WorkspaceBusyOrReclaiming is expected only when a pre-existing reclaim-owned state (CleanupFailed, OrphanPending, or no-row orphan leaf) already exists. Error::WorkspaceAlreadyExists is not part of this race's expected set.`

3. [780] — The section header still does not show the full typed signature the body now depends on.
   **Fix:** `### 3.6 cleanup_workspace(workspace, reason, registry_row: Option<&Row>) → Result<(), Error>`
