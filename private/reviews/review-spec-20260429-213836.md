## Findings

### 🔴 Critical
1. [docs/specs/spec-caduceus-orchestrator-algorithm.md:880-906] — `on_retry_timer`'s `TrackerClass::Terminal` arm drains maps and explicitly skips a `recent_history_ring` write, but the claimed earlier writer is not guaranteed to exist. `on_worker_exit` already removed the run from `state.running`, and §3.2 cascade writers iterate `state.running`, so this retry-pending run is invisible to them. **Fix:** Replace L892-L895 with:

```text
// No §3.2 cascade site can have written this run's terminal summary:
// all such sites iterate `state.running`, and this run left
// `state.running` in `on_worker_exit`. Therefore this retry-fire
// `TrackerClass::Terminal` arm MUST be the canonical finalize site and
// MUST emit exactly one `recent_history_ring` entry before draining maps.
```

2. [docs/specs/spec-caduceus-orchestrator-algorithm.md:352-369] — The postcondition discussion overclaims closure by treating eventual token-drain on retry-fire as if it also proved earlier terminal-summary publication. It does not. **Fix:** Replace the paragraph at L352-L369 with:

```text
If the helper is invoked on a `run_id` that is not in `state.running`
(early-return at line 298), postconditions 1, 2, 3, 5, 6, and 7 are
trivially satisfied (no entry to act on), postcondition 4 takes its
second arm (no ring write), and postcondition 8 is satisfied only for
live-map cleanup. This early-return does NOT prove that any prior
terminal-summary ring write occurred for retry-pending reclassification
paths in `on_retry_timer`; those paths MUST specify ring-write behavior
explicitly.
```

### 🟡 Important
1. [docs/specs/spec-caduceus-orchestrator-algorithm.md:1418-1426] — The invariant text correctly enumerates token-drain sites, but it still blurs drain-only paths together with retry-pending reclassification paths that need an explicit ring-write contract. **Fix:** Replace L1418-L1426 with:

```text
Additional `on_retry_timer` sites split into two classes: (a)
non-terminal abandon paths, which drain maps only (`run vanished from
WorkSource`, dispatch-defer abandon), and (b) retry-pending
reclassification paths (`TrackerClass::{Terminal, Neither}`), which MUST
state explicitly whether they emit exactly one
`FinishedRunSummary` before draining `token_totals` and
`last_reported_tokens`. This spec MUST make that choice explicit rather
than implying it was guaranteed elsewhere.
```

2. [docs/specs/spec-caduceus-orchestrator-algorithm.md:782-786] — The `push_finished` doc is locally correct, but the surrounding writer set is incomplete because retry-fire reclassification still has no explicit canonical writer. **Fix:** Replace L782-L786 with:

```text
/// Project a finished `RunningEntry` into a `FinishedRunSummary` and
/// write it to `recent_history_ring` (Y-4). FIFO eviction at insertion
/// when the ring is full. Called on terminal finalize paths that own a
/// well-formed summary source: `terminate_and_finish` (§3.1),
/// `on_worker_exit`'s true terminal finalize path, and any retry-fire
/// finalize path explicitly defined by §3.5.
```

3. [docs/specs/spec-caduceus-orchestrator-algorithm.md:973-1008] — The defer-abandon commentary is fine for drain semantics, but the spec still repeats open-coded per-run drains in multiple branches. **Fix:** Add after L314:

```rust
fn drain_retry_pending_state(state: &mut OrchestratorState, run_id: &RunId) {
    state.running.remove(run_id);
    state.claimed.remove(run_id);
    state.retry_attempts.remove(run_id);
    state.dispatch_defer_attempts.remove(run_id);
    state.token_totals.remove(run_id);
    state.last_reported_tokens.remove(run_id);
}
```

and replace each repeated drain block in `on_retry_timer` with:

```rust
drain_retry_pending_state(state, &run_id);
```

4. [docs/specs/spec-caduceus-orchestrator-algorithm.md:2007+] — The test matrix still lacks the exact failing path: worker exits to retry-pending, WorkSource flips Terminal before retry fire, retry timer becomes the first observer. **Fix:** Add:

```text
### T-B21: Terminal reclassification during retry-pending window

**Setup.** Dispatch `R1`. The worker exits `Normal`, so `on_worker_exit`
schedules a retry and removes `R1` from `state.running` while keeping it
claimed. Before the retry timer fires, the WorkSource reclassifies `R1`
as `Terminal`.

**Expected.** When `on_retry_timer` fires, it MUST emit exactly one new
`FinishedRunSummary` for `R1` to `recent_history_ring` before draining
`claimed`, `retry_attempts`, `dispatch_defer_attempts`,
`token_totals`, and `last_reported_tokens`. No worker is respawned and
no further retry is scheduled.
```

## Recommended Actions
1. Make retry-fire `TrackerClass::Terminal` and `TrackerClass::Neither` explicitly own ring-write semantics instead of claiming an earlier cascade already did.
2. Tighten the postcondition and invariant prose so token-map cleanup is not conflated with terminal-summary publication.
3. Add a dedicated test for the retry-pending Terminal/Neither reclassification path.
4. Factor repeated drain blocks into a single helper to match the spec's own anti-open-coding guidance.
