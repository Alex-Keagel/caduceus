## Findings

### 🔴 Critical
1. [L880-L911, L1383-L1388] `on_retry_timer` says it MUST NOT write `recent_history_ring`, but the run has already been removed from `state.running` by `on_worker_exit` (L708-L711), so none of the §3.2/§3.4 cascade sites can guarantee a write. **Fix:** make the retry-pending `TrackerClass::Terminal` arm the canonical terminal-finalize writer for that state, and update the writer invariant accordingly.

2. [L352-L369, L1418-L1426] B21 now enumerates token-drain sites, but it still treats the retry-timer `Terminal` arm as drain-only. That closes the token leak, not the missing cascade-summary write. **Fix:** require the `Terminal` arm to append exactly one `FinishedRunSummary` before draining.

### 🟡 Important
1. [L786, L1383-L1388] The documented writer set is stale. It still says only `push_finished` via `on_worker_exit` and `terminate_and_finish` can write the ring, which makes the retry-pending terminal path impossible to specify correctly. **Fix:** add the retry-pending terminal-finalize path to the normative writer list.

2. [L973-L1003] The defer-cap abandon discussion correctly explains why no terminal finalize will fire there, but the nearby comments create a misleading symmetry with the retry-timer `Terminal` arm. **Fix:** explicitly distinguish “abandon/no terminal summary” from “terminalize/must write summary.”

### 🟢 Suggestions
1. [L863-L867, L896-L901, L912-L917, L1004-L1008] Extract the repeated per-run drain sequence into a small helper so the state-machine closing edges are auditable by grep.

## Recommended Actions
1. Add enough retry-pending metadata to finalize a run from `RetryEntry` (or preserve a finalizeable snapshot elsewhere) so the retry-timer `Terminal` arm can emit a `FinishedRunSummary`.
2. Rewrite the `TrackerClass::Terminal` arm in `on_retry_timer` to finalize-then-drain exactly once.
3. Update the ring single-writer invariant and the drain-site prose to reflect the retry-pending terminal path.
4. Add a test that starts from `on_worker_exit(Normal|Abnormal)` → retry-pending → `classify(run)==Terminal` and asserts one new ring entry, never zero and never two.
