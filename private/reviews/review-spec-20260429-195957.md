1. **[spec-multi-repo-workspace-model.md:351-352, 445-517, 1346]** — `§3.5` still contradicts itself on `EEXIST`. Step 1.2 rejects any pre-existing row, but step 5b's table tries to distinguish `CleanupFailed`/`OrphanPending`; and for the no-row orphan-leaf case, step 1.4's freshly inserted `Creating` placeholder becomes the "matching row" that step 5b sees, so the spec's own `alive()` rule classifies the orphan as a duplicate instead of reclaimable.
   **Fix:** Replace step 1.2 with:
   > 2. Look up any pre-existing registry row for `(slug, sanitize_run_id(run_id)))` **before** inserting the placeholder from step 1.4. If no row exists, continue. If a row exists in `Status::Creating`, `Status::Active`, or `Status::CleaningUp`, release the mutex and return `Error::WorkspaceAlreadyExists`. If a row exists in `Status::CleanupFailed` or `Status::OrphanPending`, idempotently enqueue `OrphanReclaim { slug, run_id }`, release the mutex, and return `Error::WorkspaceBusyOrReclaiming`.

   and insert after line 447:
   > The registry-row lookup used by the step 5b discriminator table is against the **pre-step-1.4 snapshot** captured under the registry-wide mutex. The `Status::Creating` placeholder inserted by the current invocation MUST NOT be treated as the "matching row" for this table.

2. **[spec-multi-repo-workspace-model.md:1618-1620, 1640, 1719-1736]** — The `OrphanReclaim` queue contract is still inconsistent. `§5B.1` `Active` enqueues `OrphanReclaim { workspace_id }`, but `§5B.2` step 4 and step 7 define the queue key as `{ slug, run_id }`; and `§5B.1` `OrphanPending` still bypasses the queue with a direct `→ CleaningUp`, contradicting step 7's "queue remains the single canonical reclaim path" rule.
   **Fix:** Replace the `§5B.1` `Active` row action text with:
   > §3.6 step 4 layered liveness probe (heartbeat file + pid+pgrp). Alive ⇒ leave `Active`. Disproved ⇒ enqueue `OrphanReclaim { slug, run_id }`; row stays in `Active` until reconcile drains the queue (consistent with §5B.2 steps 4 and 7). Inconclusive ⇒ `OrphanPending`.

   Replace the `§5B.1` `OrphanPending` row action text with:
   > Re-run §3.6 step 4 on each reconcile pass. Once liveness is positively disproved, enqueue `OrphanReclaim { slug, run_id }`; the row stays in `OrphanPending` until reconcile drains the queue, re-enters §3.6 from step 3, and transitions to `CleaningUp` at §3.6 step 1. Direct synchronous `OrphanPending → CleaningUp` outside queue drain is FORBIDDEN.

### 🟡 Important

   > When the reconcile loop drains an `OrphanReclaim { slug, run_id }` enqueued by this step 5 (no matching registry row), it MUST invoke `cleanup_workspace` with a synthetic `Workspace` **and an explicit cleanup context `registry_row = None`**. `parent_dev_ino` remains registry metadata, not a `Workspace` field.
