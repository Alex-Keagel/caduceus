## Findings

### 🔴 Critical
1. [§3.4] Clause (b) says boot_id mismatch but detects via generic fingerprint inequality. **Fix:** split it into fingerprint mismatch semantics or explicitly scope it to boot_id only.
2. [§3.4] Clause (a) uses `recent_history_ring_size` for delta replay gap. **Fix:** use a replay-window tied to broadcast retention, not finished-run history.
3. [§4.5 / §4.8] `RunDetail` sub-collections and `RateLimitBlob.raw` are not bounded. **Fix:** cap all collections and raw payload bytes normatively.

### 🟡 Important
1. [§3.1] `runtime_total` and `next_poll_at` still mix monotonic and projected wall-clock domains. **Fix:** use captured `mono_now` and project `next_poll_at` explicitly.
2. [§3.2 / §4.9] `Run(run_id)` behavior for retry-only runs is not defined. **Fix:** add `RunNotRunnable` or equivalent explicit error.
3. [§3.3 / §3.4.1 / §6] stream and ack shapes are inconsistent across prose and tests. **Fix:** define request/ack/frame shapes once and make tests match.

### 🟢 Suggestions
1. [§4.1.1] Remove `Retrying` from `RunStatus`; represent retry state only via `RetryRow`.
2. [§4.4] Rename `last_event_max_chars` to `last_event_max_bytes` everywhere.

## Recommended Actions
1. Replace §3.4 clause (a)/(b) with unambiguous replay-gap and fingerprint-mismatch rules.
2. Add hard bounds for every variable-size payload exposed by `RunDetail` and `RateLimitBlob`.
3. Align test contract with actual ack/frame wire shapes and token field names.
