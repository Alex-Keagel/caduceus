## Findings

### 🟡 Important
1. [docs/specs/spec-caduceus-agent-runner-contract.md:883, 321-462] — Schema says inbound `run_id` must match env/run, but §3.2 read loop never validates `event.run_id == runner.run_id` before forwarding.
   **Fix:** Add explicit check before seq handling: on mismatch emit `protocol_violation` (`reason="run_id_mismatch"`) and `stop_cascade`.

2. [docs/specs/spec-caduceus-agent-runner-contract.md:1000-1007, 449-462] — Spec declares closed message-kind set and mandates `unknown_message_kind` termination, but §3.2 algorithm has no unknown-kind gate and forwards parsed events directly.
   **Fix:** Add `if event.kind not in ALLOWED_INBOUND_KINDS => emit protocol_violation + stop_cascade(reason="unknown_message_kind")` before wrap/forward.

3. [docs/specs/spec-caduceus-agent-runner-contract.md:791-794, 767-783] — Rule 2 says under saturation runner MUST first drop/coalesce non-authoritative `turn_event` telemetry, but mandatory-frame branch only waits and then kills run; it never evicts existing droppable telemetry to make room.
   **Fix:** Define mandatory-path make-room step: evict/coalesce queued non-authoritative `turn_event` entries first, then retry enqueue before `runner_backpressure` escalation.

## Recommended Actions
1. Wire the three fixes into §3.2/§3.5.1 pseudocode.
2. Add corresponding tests in §6 (run_id mismatch, unknown kind, mandatory enqueue with droppable telemetry present).
