## Findings

### 🔴 Critical
1. [§3.4 lines 361-367, 402-409, 421-450, 573-590; §3.4.1 lines 517-529; §6 T-6/T-7/T-13] — The reconnect contract is internally contradictory: the prose defines `SubscribeAck` as tagged variants, §3.4.1 defines a struct with `body`, the first-delta rule forbids replay, and worked example 2 still claims seq 10/11 replay to a reconnecting subscriber. This will produce incompatible implementations. **Fix:** replace the full `§3.4 Stream protocol` paragraph, Clause (a), and the worked example 2 block with the exact text from the chat review.
2. [§4.1 lines 701-706, 729-736; §4.8 lines 1083-1099] — The spec leaks host-local data (`pid`, absolute `workspace_path`) and permits an unbounded `RateLimitBlob.raw` payload to be rebroadcast indefinitely. With auth deferred, that is not a future problem; it is a v1 defect. **Fix:** replace the `pid` note and the §4.8 paragraph with the exact text from the chat review; also change `workspace_path: AbsolutePath` to `workspace_path: Option<AbsolutePath>`.

### 🟡 Important
1. [§3.2 lines 224-256; §4.5 lines 893-900] — `RunDetailOptions` is referenced normatively but cannot be supplied by the RPC surface. `BudgetTooSmall` also references a caller-supplied timeout that is absent from the request shape. **Fix:** replace the §3.2 signature/inputs block with the exact `dispatch_snapshot_request(request_id, scope, options)` text from the chat review and replace the §4.5 configurability paragraph accordingly.
2. [§4.1.1 lines 741-749] — `RunStatus::Retrying` is dead state on `RunRow`; retry is modeled by `RetryRow`, not a live-row enum. Keeping it here muddies the wire contract and enum-tag meaning. **Fix:** replace §4.1.1 with the exact two-variant enum text from the chat review.
3. [§3.4.1 lines 532-536] — The spec says it is transport-neutral, then makes field order on the wire normative for all encodings. That is false for self-describing transports. **Fix:** replace the `Field order on the wire` paragraph with the exact `Encoding rule (normative)` text from the chat review.
4. [§3.1 step 4; §4.8] — `RateLimitBlob` selection is undefined when multiple active runners have different rate-limit states. `most recent` is not a comparator. **Fix:** replace §3.1 step 4 with the exact highest-`runner_seq` rule from the chat review.

### 🟢 Suggestions
1. [§4.4 lines 845, 851-856; §3.1 line 95] — The option name says `last_event_max_chars` while the rule truncates by bytes. **Fix:** rename it to `last_event_max_bytes` everywhere.
2. [§6 lines 1411-1427] — T-17 appears before T-16. **Fix:** renumber T-17/T-16 into monotonic order.
3. [§0/§2 throughout] — X/Y/Z tags are opaque with no legend. **Fix:** add the `Reference tag prefixes` paragraph from the chat review.

## Recommended Actions
1. Normalize `SubscribeAck` to a single shape and remove the replay claim from the reconnect example.
2. Put hard v1 limits on sensitive fields and untrusted payload sizes.
3. Make request options explicit in the RPC surface and test the edge cases they introduce.
