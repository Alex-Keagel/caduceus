One paragraph says control transfers directly to step 5b; the next says that happens only after step 5b's `EEXIST`. That leaves the no-`EEXIST` path underspecified and makes step 9/10 still talk about a placeholder that step 1.4 forbids inserting.
   **Fix:** Replace lines 351-370 with:
   ```md

      row exists for `(slug, sanitize_run_id(run_id))` with
      `Status ∈ {Creating, Active, CleaningUp}`, the spawn MUST fail
      with `Error::WorkspaceBusy` — release the registry-wide mutex
      first. If a row exists with `Status ∈ {CleanupFailed,
      OrphanPending}`, the daemon MUST enqueue
      `OrphanReclaim { slug, run_id }` onto the reconcile queue,
      preserve the existing row unchanged, release the per-workspace
      lock, the per-slug guard, and the registry-wide mutex in
      reverse-acquire order, and return
      `Error::WorkspaceBusyOrReclaiming`. Steps 1.4–9 MUST NOT run on
      this branch. The current invocation's own `Creating` placeholder
      (inserted at step 1.4 only when no row was found here) MUST NOT
      count as a matching row for any later lookup within this spawn.
   ```
   Replace lines 408-417 with:
