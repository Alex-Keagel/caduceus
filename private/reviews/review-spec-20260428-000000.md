## Findings

### 🔴 Critical
1. [§3.1 step 6] `next_poll_at = state.next_poll_scheduled` violates the spec’s own monotonic→wall-clock projection rule. **Fix:** replace step 6 with projected `state.next_poll_scheduled.map(project)` text.
2. [§3.4 stream protocol + worked example] `UpToDate` ack says first delivered delta must satisfy `delta.stream_seq > ack.stream_seq`, but the example says deltas 10 and 11 replay after `ack.stream_seq = 11`. **Fix:** forbid replay of deltas `<= ack.stream_seq`; otherwise emit `Resync`.
3. [§1.2, §4.1, §4.8, §7] Auth is out of scope while the wire shape exposes `pid`, `workspace_path`, and opaque `raw` / error payloads. **Fix:** add v1 transport-security baseline and `AccessDenied` error contract.

### 🟡 Important
1. [§3.2, §4.5, §4.9] Request shape is incomplete: `BudgetTooSmall` and `RunDetailOptions` exist, but request inputs do not carry timeout or detail options. **Fix:** replace the input contract with a `SnapshotRequest` struct that includes `snapshot_timeout_ms` and `run_detail_options`.
2. [§3.3] `fields_changed: Map<String, JsonValue>` has no canonical closed key set. **Fix:** add normative `fields_changed` key table and version rule.
3. [§4.2.1] Spec #4 requires truncation before storing into `RetryEntry`, but `RetryEntry` is owned by spec #1. **Fix:** move storage-time truncation ownership to spec #1; make spec #4 projection-only.

### 🟢 Suggestion
1. [§1.2 vs §7; §8; §6] Duplicate out-of-scope text, “Open questions” containing settled decisions, and T-17/T-16 ordering create avoidable maintenance noise. **Fix:** make §7 the single normative scope source, rename §8, and renumber tests monotonically.

## Recommended Actions
1. Fix reconnect semantics and clock-domain projection first.
2. Add mandatory access-control/redaction/bounds before implementation starts.
3. Close the wire contract: request shape, delta key set, and payload size limits.
