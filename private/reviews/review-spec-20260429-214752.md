## Findings

### 🔴 Critical
1. **[docs/specs/spec-caduceus-orchestrator-algorithm.md:880-907]** `on_retry_timer` still permits a zero-entry terminal path. After `on_worker_exit` removes a retry-pending run from `state.running`, the §3.2 cascade sites cannot see it, so the `TrackerClass::Terminal` arm is the only remaining place that can guarantee a `recent_history_ring` write. B21 still drains maps and returns without writing one.
   **Fix:** Replace lines 880-907 with:

```rust
    match state.work_source.classify(&run) {
        TrackerClass::Terminal => {
            // Retry-pending runs are no longer in `state.running`, so the
            // §3.2 cascade sites cannot finalize them. This arm is therefore
            // the canonical terminal-finalize path for a run that becomes
            // Terminal between `on_worker_exit` and retry fire.
            finalize_retry_pending_run(
                state,
                &run,
                &rentry,
                ExitReason::DaemonTerminated {
                    cause: TerminationCause::WorkSourceTerminal,
                },
            );
            return;
        }
        TrackerClass::Neither => {
            finalize_retry_pending_run(
                state,
                &run,
                &rentry,
                ExitReason::DaemonTerminated {
                    cause: TerminationCause::WorkSourceLeftQuery,
                },
            );
            return;
        }
        TrackerClass::Active => {
            // Fall through to normal retry-timer body.
        }
    }
```

2. **[docs/specs/spec-caduceus-orchestrator-algorithm.md:352-367, 1418-1426]** The prose now enumerates extra drain sites, but it still normalizes the broken behavior by saying the retry-fire `Terminal`/`Neither` arms are drain-only paths where “no terminal finalize will fire.” For the terminal case, a terminal finalize **must** fire here.
