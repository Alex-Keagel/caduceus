## Findings

### 🔴 Critical
1. [§6 T-13, lines 1664-1666] — Test text conflates agent `seq` (Z-24, diagnostic-only on regression) with wire `runner_seq` (protocol-fatal on gaps). This can force a wrong implementation that disconnects on stutter/regression instead of surfacing `seq_regression`.
   **Fix:** Replace T-13 with:
   `- **T-13 — Agent seq regression is diagnostic-only; wire runner_seq gaps are fatal.** (a) Inject an inbound frame whose agent-stamped \`seq\` is <= prior high-water; assert runner emits \`seq_regression\` (kind_detail \`stutter\` or \`regression\`) and continues processing. (b) Separately inject a daemon-observed \`runner_seq\` gap; assert daemon emits \`protocol_violation\` with reason \`runner_seq_gap\` and disconnects (Z-22/§4.4 invariant).`

2. [§I-9.1, lines 1466-1474] — Socket-path security omits symlink/rename TOCTOU hardening. Absolute path alone is insufficient.
   **Fix:** Append to Address/File mode text:
   `Creation/open of the broker path MUST be symlink-safe: implementations MUST create parent directories with O_NOFOLLOW semantics (or equivalent), validate each path component with lstat/fstatat(NO_FOLLOW), and refuse if any component is a symlink. The final socket path MUST be created atomically within the validated directory.`

### 🟡 Important
1. [§3.3 lines 482-500 vs §5 I-3 lines 1374-1377] — I-3 presents an upper-bound recommendation (ε ≤ 250 ms) while decomposition mandates ε₁ ≥ 100 ms plus ε₂ ≥ sigkill_reap_budget; relationship is implicit and can be misread as contradictory.
   **Fix:** Replace I-3 text in §5 with:
   `- **I-3 — StopCascade is bounded.** \`stop_cascade\` MUST return within \`ε₁ + 2 * grace_period_ms + ε₂\`, where \`ε₁ >= 100 ms\` (Z-26 enqueue-or-skip bound) and \`ε₂ >= sigkill_reap_budget\`. Implementations MAY report \`ε = ε₁ + ε₂\`; recommended \`ε <= 250 ms\` when platform reap latency permits.`

2. [§3.5.1 line 639; §4.1 table line 879] — “runners MUST NOT emit \`cross_run_handoff\`” uses the wrong actor (agents emit inbound kinds; runner forwards/wraps).
   **Fix:** Replace phrase with:
   `agents MUST NOT emit this kind in v1; if observed, runners MUST treat it as reserved-but-valid and forward it unchanged.`

3. [§I-9.1 lines 1479-1482] — “0700 prevents same-UID-different-process connect” is factually wrong; same UID can still traverse/connect. Security actually depends on peer auth + lineage.
   **Fix:** Replace sentence with:
   `Directory mode 0700 prevents cross-UID traversal; it does not block same-UID peers. Therefore SO_PEERCRED/LOCAL_PEERCRED plus mandatory PID-lineage validation is the load-bearing same-UID defense.`

4. [§I-9.1 lines 1490-1495] — PID lineage check is underspecified for PID reuse races.
   **Fix:** Add:
   `Lineage validation MUST be reuse-safe: implementations MUST validate process start-time/creation-time for the AgentProcess and candidate peer ancestry, and MUST reject if ancestry cannot be proven with stable identity metadata.`

## Recommended Actions
1. Fix T-13 wording to separate agent `seq` diagnostics from `runner_seq` protocol-fatal invariants.
2. Harden I-9.1 with symlink-safe path creation and PID-reuse-safe lineage checks.
3. Normalize I-3 wording to the ε₁ + 2·grace + ε₂ form and keep ε<=250 as recommendation, not hidden constraint.
4. Correct `cross_run_handoff` emitter actor language.
