## Findings

### 🔴 Critical
1. [docs/specs/spec-caduceus-agent-runner-contract.md:97,301-302,322-323,350-351,494-507,525-527,542-544,565-567,591-593,623-625,696-706,1011-1013,1303-1304] — The spec now defines `GraceWindow` correctly as the composite envelope, but call sites still pass that composite into `stop_cascade(..., grace_period_ms)`, and §3.3 then expands it again as `ε₁ + 2*grace_period_ms + ε₂`. That breaks I-3/T-1/T-9 and exposes the same bug iter-22 was supposed to retire.
   **Fix:** Replace the API boundary, not just the prose. Exact action:
   - Replace the §3.3 signature/header line
     `### 3.3 \`stop_cascade(runner, reason, grace_period_ms)\``
     with
     `### 3.3 \`stop_cascade(runner, reason)\``
   - Replace
     `stop_cascade(runner, reason, grace_period_ms):`
     with
     `stop_cascade(runner, reason):`
   - Insert immediately after the signature:
     ```text
         let grace_period_ms = runner.config.grace_period_ms
         deadline_total = now() + ε₁ + (2 * grace_period_ms) + ε₂
     ```
   - Delete the named argument `grace_period_ms = GraceWindow` at every listed call site.

### 🟡 Important
1. [docs/specs/spec-caduceus-agent-runner-contract.md:596-651,1295-1305] — `malformed_payload` is normative, but §3.2 never performs payload-schema validation before delivery / side effects. The fail-closed path is declared, not wired.
   **Fix:** Insert this block after the unknown-kind guard and before `wrapped = {`:
   ```text
                   match validate_payload_schema(event.kind, event.payload):
                       Ok => {}
                       Err(field_name) => {
                           emit_event(daemon_event_channel, {
                               kind:       "malformed_payload",
                               run_id:     runner.run_id,
                               frame_kind: event.kind,
                               field:      field_name,
                           })
                           stop_cascade(runner, reason = "malformed_payload")
                           return Err(RuntimeError::MalformedPayload)
                       }
   ```

2. [docs/specs/spec-caduceus-agent-runner-contract.md:2098-2310] — §6 still lacks explicit tests for the two fail-closed runtime guards that this iteration depends on: `unknown_message_kind` and `malformed_payload`.
   **Fix:** Append after T-13:
   ```markdown
   - **T-14 — Unknown message kind is fail-closed.** Emit a frame whose
     `kind` is not present in either §4.1 kind table. Assert
     `protocol_violation` with `reason = "unknown_message_kind"` and
     `stop_cascade(reason = "unknown_message_kind")`.

   - **T-15 — Malformed runtime payload is fail-closed.** After a valid
     handshake, emit a runtime frame with a missing required field, and a
     second runtime frame with a type-mismatched required field. Assert
     `malformed_payload`, `field = <violating field>`, and
     `stop_cascade(reason = "malformed_payload")`.
   ```

3. [docs/specs/spec-caduceus-agent-runner-contract.md:1993-2002] — Broker peer authentication still permits PID-only lineage checks. Same-UID PID reuse can satisfy “descendant of AgentProcess PID” after the original process exits.
   **Fix:** Append after line 2002:
   ```markdown
   The broker MUST bind lineage validation to `(pid, process_start_time)`,
   not PID alone. The daemon MUST record the spawned AgentProcess start
   time at spawn, and on connect the broker MUST verify both lineage and
   start-time equality (Linux: `/proc/<pid>/stat` field 22; macOS:
   `proc_pidinfo`; Windows: process creation time). PID-only lineage
   checks are insufficient and MUST be rejected.
   ```

4. [docs/specs/spec-caduceus-agent-runner-contract.md:2383-2392,2406-2409] — §8.4 still says retry ownership is an “Open question” even though §9 already assigns retry policy to spec #1. That is a spec-internal contradiction.
   **Fix:** Replace §8.4 with:
   ```markdown
   ### 8.4 Boundary with spec #1: retry ownership on `Abnormal` exit

   Per **I-7** and §9, retry classification is owned exclusively by
   spec #1's orchestrator. The runner MUST emit raw `exit_code` and
   `exit_reason` only and MUST NOT emit recoverability hints derived
   from stderr text, exit-code heuristics, or vendor-specific pattern
   matching. Any retry / backoff / abandonment decision is outside this
   contract.
   ```

## Recommended Actions
1. Fix the `stop_cascade` API boundary and remove all `grace_period_ms = GraceWindow` call-site arguments.
2. Wire `malformed_payload` enforcement into §3.2 and add T-14/T-15.
3. Tighten broker auth to `(pid, process_start_time)`.
4. Resolve §8.4 so spec #1 ownership is normative, not advisory.
