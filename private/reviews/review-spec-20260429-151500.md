## Findings

### 🔴 Critical
1. [436-459, 506-520, 542-560] — `UpToDate` single-source-of-truth is still internally contradictory: lines 447-459 say fingerprint equality alone makes the subscriber already consistent at `ack.stream_seq` regardless of path, but lines 506-520 and clause (a) still force `Resync` on large gaps even when current fingerprint matches. **Fix:** Replace the first two bullets of "First-delta rules" with:

```md
- `subscribe(channel, since_fingerprint = Some(current_fingerprint), since_stream_seq = Some(s_c), since_boot_id)`
  where `boot_id` is unchanged AND no force-resync clause except clause (a)'s
  gap-only arm fires
  ⇒ **`UpToDate`**: subscriber retains its local snapshot because current-fingerprint
  equality already establishes state equivalence at `ack.stream_seq`; the subscriber
  adopts `ack.stream_seq = current_stream_seq` and receives only live deltas with
  `stream_seq > ack.stream_seq`.
- `subscribe(channel, since_fingerprint, since_stream_seq = Some(s_c), since_boot_id)`
  where `boot_id` differs OR `current_stream_seq < s_c` OR the force-resync clauses
  (b), (c), (d), (P) fire
  ⇒ **`Resync { snapshot, stream_seq }`**: subscriber discards local state; live-only
  deltas after that, no replay window.
```

2. [438-445, 531-533, 557-560, 605-608, 628-629, 653-655, 1604-1613, 1659-1661] — `SubscribeAck` is still described with two incompatible wire shapes: enum-style `SubscribeAck::UpToDate/Resync` in §3.4 and tests, versus struct-with-`body` in §3.4.1. **Fix:** Replace lines 438-445 with:

```md
**Stream protocol.** First message is `SubscribeAck { version, boot_id, fingerprint, stream_seq, body }`, where `body` is either `UpToDate` or `Resync { snapshot: AggregateSnapshot }`. Thereafter, `SnapshotDelta` messages are delivered until disconnect.
```

Then replace each remaining `SubscribeAck::UpToDate` / `SubscribeAck::Resync` reference in §3.4 and tests with the struct form defined in §3.4.1 (for example, T-6/T-7/T-13 should say `ack.body: Resync { snapshot }` / `ack.body: UpToDate`).

### 🟡 Important
1. [731-735] — §3.4.1 still says the defensive re-subscribe after a cross-boot `UpToDate` bug routes to clause (b), but `since_fingerprint = None` unconditionally routes to clause (c) per lines 618-625. **Fix:** Replace lines 731-735 with:

```md
`boot_id`), defensively close the subscribe stream and re-subscribe
with `since_fingerprint = None`, `since_stream_seq = None`, and
`since_boot_id = Some(<last_known_boot_id>)`. This forces clause (c)'s
baseline path; `since_boot_id` is still carried so the daemon and
subscriber can log the cross-boot mismatch explicitly.
```

2. [646-649, 663-664] — `ring_oldest_seq` is normative input to clauses (d)/(P) but is never defined, so replay-index boundary behavior is underspecified. **Fix:** Insert after line 649:

```md
For §3.4, `ring_oldest_seq` means the smallest `stream_seq` key currently
retained in the daemon-owned delta replay index. After each published
`SnapshotDelta(stream_seq = s)`, the daemon MUST insert `(s -> snapshot_fingerprint)`
and evict oldest entries until the index contains at most
`recent_history_ring_size` items. When the index is empty, define
`ring_oldest_seq = current_stream_seq`.
```

3. [1586-1589] — T-3 asserts on `RunRow.tokens.absolute_total`, but §3.1 step 1 and §4.7 define `RunRow.tokens` as `TokenTotals`, which does not contain an `absolute_total` field. **Fix:** Replace lines 1586-1589 with:

```md
Drive a runner that emits `delta {input: 100, output: 50}` then
`absolute {input: 1000, output: 500}` within one turn. Resulting
`RunRow.tokens.input_tokens` MUST be 1000 and
`RunRow.tokens.output_tokens` MUST be 500 (NOT additive 1100/550);
`tokens_aggregate` MUST agree. Verifies I-3.
```
