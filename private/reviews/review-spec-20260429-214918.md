## Findings

### 🔴 Critical
1. [L829-L1031] `on_retry_timer` violates SRP and obscures retry/cascade ownership boundaries. **Fix:** split into helpers and make `on_retry_timer` a coordinator only.
2. [L352-L370, L848-L1008] The spec lacks a normative architectural rule distinguishing `terminate_and_finish` from non-finalizing stale-state drain. **Fix:** add a helper-ownership rule and a dedicated retry-path drain helper.
3. [L1977-L2030] T-4 asserts an ordering that contradicts `terminate_and_finish`; the test contract is currently wrong. **Fix:** restate T-4 to match the helper's normative sequence.

### 🟡 Important
1. [L893-L895, L2407-L2409] Wrong internal section references (`§3.4`). **Fix:** change to `§3.2` and `§3.5`/`§4` as appropriate.
2. [L767-L779, L1672-L1675, L1550] Token reuse semantics are implicit and can be implemented incorrectly. **Fix:** explicitly define generation allocation, reuse, supersession, and restart behavior.
3. [After L1905] “Exactly one ring entry per cascade” exists only in comments/tests. **Fix:** promote to invariant I-14.
4. [L881-L917] `running.remove` appears in only some stale-cleanup branches, suggesting false semantic differences. **Fix:** centralize drain and make behavior symmetric.

### 🟢 Suggestions
1. [L723-L731, L1538-L1545] Bound and redact retry `error_message` before storage/egress.
2. [L216, L1337, L1707] Qualify `§3.4 SubscribeAck` as `spec #4 §3.4 SubscribeAck` to remove cross-spec ambiguity.

## Recommended Actions
1. Replace `on_retry_timer` with a coordinator plus helpers: `drain_retry_owned_state`, `requeue_retry`, `handle_deferred_retry`.
2. Add a normative helper-ownership rule after `terminate_and_finish`.
3. Add invariant I-14 after I-13.
4. Fix wrong section refs and T-4 ordering text.
5. Make `RetryToken` semantics explicit and add redaction/bounding language for retry errors.
