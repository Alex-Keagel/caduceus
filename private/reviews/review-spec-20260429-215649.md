## Findings

### 🔴 Critical
1. **[§3.5 `on_retry_timer` Terminal arm, ~L881-L906]** No guaranteed prior ring write; claim is incorrect.
   - `on_worker_exit` removes `state.running[run_id]` before scheduling retry.
   - `reconcile_running_runs` only scans `state.running.keys()`; retry-pending runs are invisible.
   - Therefore timer callback can hit `TrackerClass::Terminal` with no prior `terminate_and_finish` and no ring write.

   **Fix (exact replacement text for Terminal arm comment block):**
   ```rust
   // Retry-pending run reclassified Terminal. No RunningEntry is in scope
   // on this path (it was consumed by on_worker_exit when retry was
   // scheduled), so this arm MUST NOT call push_finished.
   //
   // IMPORTANT: There is also NO guarantee that a prior §3.2 cascade wrote
   // a ring entry for this run. Reconcile iterates only state.running; this
   // run is retry-pending, not running. This path is therefore explicitly
   // "no-ring-write" and only reclaims live maps.
   //
   // If product requirements need a terminal summary here, the spec MUST add
   // a RetryEntry-carried terminal projection (or equivalent) and define it
   // as an additional canonical writer.
   ```

2. **[§3.5 `on_retry_timer` Neither arm, ~L908-L922]** Same no-ring-write gap, but not stated as explicit contract.

   **Fix (exact replacement text for Neither arm comment block):**
   ```rust
   // Retry-pending run reclassified Neither while no RunningEntry exists.
   // This path is symmetric with the Terminal arm above: drain retry/claim/
   // token maps and return without ring write.
   //
   // This is an explicit no-ring-write path (retry-pending runs are not
   // visible to §3.2 reconcile); diagnostics are the durable signal.
   ```
