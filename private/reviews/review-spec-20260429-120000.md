## Findings

### 🔴 Critical
1. [§1.2 “Out of scope”, lines 53–96] — The non-locally-trusted redaction profile mutates required v1 wire shapes in place (`workspace_path`, `error_message`, `last_event`, `event_log_tail`, `hook_log`, etc.). That contradicts §4’s “normative on field names and semantics” promise and makes remote clients non-interoperable by design.  
   **Fix:** Replace lines 53–96 with:

   ```markdown
   - Specific RPC transport, wire encoding, authentication, and IPC socket
     location are transport concerns and are not otherwise specified here.
     **However, the trust boundary for the v1 surface is normative:**
     the v1 snapshot and subscribe surfaces defined by this spec are
     supported **only on locally-trusted transports** (for example: Unix
     domain sockets with peer-UID verification such as `SO_PEERCRED`, or
     named pipes with the platform-equivalent peer-auth mechanism).
   - A transport that cannot establish local peer identity MUST NOT expose
     the v1 snapshot / subscribe API surface directly. It MUST either:
     (a) reject the connection before any v1 payload is serialized, or
     (b) terminate at a transport-specific proxy / gateway that defines a
     distinct, separately-versioned remote API contract.
   - Consequently, the v1 wire shapes in §4 are invariant on the wire:
     implementations MUST NOT replace required fields with alternate shapes
     such as summary objects, counters, enums, or omitted payload fragments
     in the name of redaction. Any remotely-safe projection that changes the
     shape, presence, or meaning of a v1 field requires a future spec bump.
   ```

2. [§3.2 lines 317–319; §4.1.1 lines 1410–1419; §4.5 lines 1611–1615] — `RunDetail` is defined as available for finished runs in `recent_history_ring`, but `RunRow.status` has no `Finished` state, so a historical row is unrepresentable without lying.  
   **Fix:** Replace the `RunStatus` block and the immediately following note with:

   ```rust
   enum RunStatus {
       Running,                  // live engine connection; agent producing turns.
       Retrying,                 // present in snapshot.retrying; not in snapshot.running.
       Disconnected,             // engine RPC dropped; daemon retains the live row.
       Finished,                 // historical-only: row sourced from recent_history_ring.
   }
   ```

   ```markdown
   `Retrying` only appears on `RetryRow` in practice. In
   `AggregateSnapshot`, `RunRow.status` is limited to `Running` or
   `Disconnected`; `Finished` appears only inside `RunDetail.row` when the
   detail is reconstructed from `recent_history_ring` for a completed run.
   ```

   Replace the `RunDetail` struct with:

   ```rust
   struct RunDetail {
       row:                RunRow,                                  // §4.1; `row.status` MAY be Finished for ring-backed detail.
       exit_reason:        Option<ExitReason>,                      // Some(...) iff `row.status == Finished`.
       event_log_tail:     Vec<EventRecord>,                        // spec #5; default last 100.
       token_history:      Vec<(turn: u32, totals: TokenTotals)>,
       prompt_hash_trail:  Vec<(turn: u32, hash: Bytes)>,           // 256-bit BLAKE3; spec #2 §4.
       hook_log:           Vec<HookExecutionRecord>,                // spec #3 §3.5.
       workspace:          WorkspaceMeta,                           // see WorkspaceMeta below (Z6-M1).
   }
   ```

   Replace §3.2 step 2 with:

   ```markdown
   2. **Branch on scope.** `Aggregate`: call `build_snapshot`; wrap result.
      `Run(run_id)`: look up in `state.running`, `state.retry_attempts`,
      and the bounded `recent_history_ring` (§4.5). If absent everywhere,
      return `SnapshotError::RunNotFound { run_id }`. Otherwise build
      `RunDetail` (§4.5): live rows use their current `RunStatus`, while
      ring-backed rows MUST set `RunDetail.row.status = Finished` and
      populate `RunDetail.exit_reason` from the stored terminal outcome.
   ```

### 🟡 Important
1. [§3.4 lines 942–972] — Clause-(d′) still says it is reachable only when `s_c` is indexed, then immediately defines a boot-edge case where the replay index is empty and `(d′)` still fires.  
   **Fix:** Replace lines 942–945 with:

   ```markdown
   - *Detection.* Resolve `fingerprint_at(s_c)` as follows: when
     `s_c == current_stream_seq` (including boot where both are `0`),
     `fingerprint_at(s_c)` is `current_fingerprint` and no replay-index
     lookup is required. Otherwise the daemon reads `fingerprint_at(s_c)`
     from the replay index. If `s_c` is absent from the replay index and
     `s_c != current_stream_seq`, clause (a) or clause (P) fires instead;
     clause (d′) is reachable only when `fingerprint_at(s_c)` is defined.
     Clause (d′) fires when `fingerprint_at(s_c) != last_known_fingerprint`.
   ```

2. [§3.3 lines 386–392 vs §4.3 lines 1497–1512] — `AggregateUpdated` omits `agents_max`, but `agents_max` is part of the aggregate state and is allowed to change during hot reload. Subscribers can receive a new fingerprint without enough data to update their local aggregate view.  
   **Fix:** Replace the `AggregateUpdated` variant with:

   ```rust
   AggregateUpdated { stream_seq: u64,
                      tokens_aggregate: TokenTotals,
                      runtime_total: Duration,
                      rate_limit: RateLimitBlob,
                      agents_used: u32,
                      agents_max: u32,
                      next_poll_at: Option<SystemTime>,
                      snapshot_fingerprint: SnapshotFingerprint },
   ```

   And replace the §4.6 hash-input bullet:

   ```markdown
   4. `agents_used`, `agents_max`. Any `AggregateUpdated` delta that changes
      either field MUST carry both values so subscribers can update their
      local aggregate state without forcing a full resync.
   ```

## Recommended Actions
1. Make v1 explicitly locally-trusted-only instead of shape-mutating redaction.
2. Add a representable finished-run model for `RunDetail`.
3. Collapse subscribe routing semantics to one normative source.
4. Add `agents_max` to `AggregateUpdated` and align T-3 / T-20 with the actual contract.
