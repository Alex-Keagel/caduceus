### 🔴 Critical
1. [docs/specs/spec-caduceus-orchestrator-algorithm.md:707-779, 829-923, 1372-1388, 1441-1455] — **B21 did not fully resolve C20.** `on_worker_exit` removes the `RunningEntry` immediately at lines 708-711, then for `Normal`/`Abnormal` inserts `retry_attempts[run_id]` and schedules `Cmd::RetryRun` at lines 768-779. `reconcile_running_runs` only inspects `state.running` (lines 426-452; reinforced at lines 1354-1355), so the retry-pending run is invisible to every §3.2 cascade call site. When `on_retry_timer` later classifies `Terminal` or `Neither`, the spec explicitly says **no ring write** (lines 887-895, 909-917) and then drains live maps (lines 896-901, 912-917). Result: the spec still allows live maps to be dropped with **no prior `FinishedRunSummary`**.
   **Fix:** Replace the retry-pending finalization contract with the following text:

   ```rust
   struct RetryEntry {
       attempt: u32,
       token: RetryToken,
       scheduled_at: Instant,
       reason: String,
       repo_coordinate: RepoCoordinate,
       error_message: Option<String>,
       finalize_snapshot: FinishedAttemptSnapshot,
   }

   struct FinishedAttemptSnapshot {
       run_id: RunId,
       repo_coordinate: RepoCoordinate,
       attempt: u32,
       restart_count: u32,
       started_at: Instant,
       final_tokens: TokenTotals,
   }

   async fn on_worker_exit(state: &mut OrchestratorState, run_id: RunId, reason: ExitReason) {
       let entry = match state.running.remove(&run_id) {
           Some(e) => e,
           None => return,
       };
       ...
       state.retry_attempts.insert(run_id.clone(), RetryEntry {
           attempt,
           token,
           scheduled_at: Instant::now() + Duration::from_millis(delay_ms),
           reason: retry_reason.into(),
           repo_coordinate: entry.run_snapshot.repo_coordinate.clone(),
           error_message,
           finalize_snapshot: FinishedAttemptSnapshot {
               run_id: entry.run_snapshot.id.clone(),
               repo_coordinate: entry.run_snapshot.repo_coordinate.clone(),
               attempt: entry.attempt,
               restart_count: entry.restart_count,
               started_at: entry.started_at,
               final_tokens: state.last_reported_tokens
                   .get(&entry.run_snapshot.id)
                   .cloned()
                   .unwrap_or_default(),
           },
       });
       schedule_message(after_ms = delay_ms, msg = Cmd::RetryRun { run_id, token });
   }

   match state.work_source.classify(&run) {
       TrackerClass::Terminal => {
           let rentry = state.retry_attempts.remove(&run.id).expect("fresh retry entry");
           let reason = ExitReason::DaemonTerminated {
               cause: TerminationCause::WorkSourceTerminal,
           };
           push_finished_from_retry(state, &rentry.finalize_snapshot, &reason);
           state.claimed.remove(&run.id);
           state.dispatch_defer_attempts.remove(&run.id);
           state.token_totals.remove(&run.id);
           state.last_reported_tokens.remove(&run.id);
           return;
       }
       TrackerClass::Neither => {
           let rentry = state.retry_attempts.remove(&run.id).expect("fresh retry entry");
           let reason = ExitReason::DaemonTerminated {
               cause: TerminationCause::WorkSourceLeftQuery,
           };
           push_finished_from_retry(state, &rentry.finalize_snapshot, &reason);
           state.claimed.remove(&run.id);
           state.dispatch_defer_attempts.remove(&run.id);
           state.token_totals.remove(&run.id);
           state.last_reported_tokens.remove(&run.id);
           return;
       }
       TrackerClass::Active => {}
   }
   ```

### 🟡 Important
1. [docs/specs/spec-caduceus-orchestrator-algorithm.md:352-367, 881-895, 909-917] — The prose claims eventual correctness for token cleanup, but it never repairs the missing ring-write guarantee. Lines 364-366 say `Normal`/`Abnormal` defer token drain to the subsequent `on_retry_timer` terminal arm; lines 892-895 then incorrectly claim a §3.4/§3.2 cascade site already wrote the ring entry. That cannot happen once line 708 has removed the run from `running`.
   **Fix:** Replace lines 352-367 with:

   ```text
   If the helper is invoked on a `run_id` that is not in `state.running`
   (early-return at line 298), postconditions 1, 2, 3, 5, 6, and 7 are
   trivially satisfied. Postcondition 4's "no ring write" arm is valid
   only when a prior finalize path has already appended the canonical
   `FinishedRunSummary` for this `run_id`. Retry-pending runs created by
   `on_worker_exit`'s `Normal` / `Abnormal` arms are NOT in that category:
   those arms remove the `RunningEntry` without writing the ring, so any
   later `on_retry_timer` classification to `Terminal` or `Neither` MUST
   synthesize and append the missing `FinishedRunSummary` before draining
   `claimed`, `retry_attempts`, `token_totals`, and
   `last_reported_tokens`.
   ```

3. [docs/specs/spec-caduceus-orchestrator-algorithm.md:1382-1388, 1410-1429, 1441-1455] — Ring semantics are internally inconsistent. Lines 1383-1388 say the only ring writers are `push_finished` from `on_worker_exit` and `terminate_and_finish`; lines 1420-1426 add retry-timer drain sites because no terminal finalize will fire there; lines 1441-1455 make the ring the sole source of truth for `prior_restart_count`. With the current B21 text, retry-pending `Terminal`/`Neither` paths lose both recent-history visibility and restart-count continuity.
   **Fix:** Replace ring invariant #1 with:

   ```text
   1. *Single-writer authority, multiple terminal entry points.* Only the
      daemon's main task writes to the ring (I-1). Normative ring-writing
      paths are: (a) `terminate_and_finish`, (b) the terminal
      `DaemonTerminated` defensive-finalize arm in `on_worker_exit`, and
      (c) retry-pending reclassification in `on_retry_timer` when that
      function classifies a run as `Terminal` or `Neither` after
      `on_worker_exit` has already consumed the `RunningEntry`. Path (c)
      MUST synthesize the `FinishedRunSummary` from the retry entry's
      stored finalize snapshot before draining token maps. Any path that
      removes the retry state without appending that summary violates the
      ring contract and the `prior_restart_count` contract below.
   ```

4. [docs/specs/spec-caduceus-orchestrator-algorithm.md:2007-2270] — The test suite does not include a dedicated retry-pending reclassification case. T-4 covers a still-running attempt; nothing in §6 asserts the `on_worker_exit(Normal/Abnormal)` → `on_retry_timer(Terminal/Neither)` path writes exactly one ring entry before draining maps.
   **Fix:** Add the following test text to §6:

   ```markdown
   ### T-10b: Retry-pending reclassification still appends exactly one FinishedRunSummary

   > Exercises: I-4, I-5, ring invariant #1, ring invariant #5.

   **Setup.** Dispatch `R1`, seed `state.last_reported_tokens[R1]` with a
   non-default value, then deliver `on_worker_exit(R1, ExitReason::Normal)`.
   Assert that `state.running` no longer contains `R1` and that
   `state.retry_attempts[R1]` exists. Before the scheduled `Cmd::RetryRun`
   fires, configure `work_source.fetch_by_ids([R1])` to return `R1`
   classified first as `Terminal`, then in a separate variant as `Neither`.

   **Expected.**

   1. `on_retry_timer` appends exactly one `FinishedRunSummary` for `R1`
      before removing `claimed[R1]`, `retry_attempts[R1]`,
      `token_totals[R1]`, and `last_reported_tokens[R1]`.
   2. The `Terminal` variant writes
      `ExitReason::DaemonTerminated { cause: WorkSourceTerminal }`; the
      `Neither` variant writes
      `ExitReason::DaemonTerminated { cause: WorkSourceLeftQuery }`.
   3. The appended summary carries the pre-seeded engine-attested
      `final_tokens` value.
   4. A stale retry timer for the superseded token does not append a second
      ring entry.
   ```

## Recommended Actions
1. Treat B21 as **not sufficient**; the no-ring-write bug still exists for retry-pending `Terminal`/`Neither` reclassification.
2. Preserve a finalize snapshot across the retry window and make `on_retry_timer` write the canonical `FinishedRunSummary` before draining maps.
3. Replace stale line-based references with section/function references.
4. Add a dedicated §6 test that covers retry-pending reclassification and asserts one ring entry plus token-map drain ordering.
