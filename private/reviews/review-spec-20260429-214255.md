## Findings

### 🔴 Critical
1. [docs/specs/spec-orchestrator-status-snapshot.md:2306-2309] — **T-31a contradicts Z-29 lock-step trim.** T-31a requires buffer eviction while replay index still retains the same entry, but Z-29 requires atomic co-trim and forbids one-sided retention holes.
   **Fix:** Replace lines 2304-2311 with:
   ```md
   ### T-31a: ReplayCancelled under atomic lock-step trim

   A subscriber requests replay of `[s_c+1 .. current]`. During replay,
   DoS-clamp ring rotation atomically trims a required `stream_seq` from
   BOTH the replay index and the delta payload buffer (per Z-29
   sub-invariant 3). Daemon MUST emit
   `PostAckFrame::ReplayCancelled { stream_seq, reason: ReplayCancelReason::LockStepTrimRace }`
   and terminate the stream. Subscriber MUST re-subscribe with a fresh
   handshake to receive a `Resync`.
   ```
2. [docs/specs/spec-orchestrator-status-snapshot.md:2315-2320] — **T-31b requires impossible receipt-blocking.** The spec's stream model is at-most-once/no per-subscriber ack; the daemon cannot wait for subscriber receipt before trimming, and doing so violates the no-back-pressure rule.
   **Fix:** Replace lines 2313-2320 with:
   ```md
   ### T-31b: ReplayCancelled is write-then-close, not receipt-blocked

   A subscriber's replay is in progress when an atomic lock-step trim
   evicts the under-replay window. Daemon MUST detect the race, emit
   `PostAckFrame::ReplayCancelled { stream_seq, reason: ReplayCancelReason::LockStepTrimRace }`,
   and terminate the stream. The trim/cancel path MUST NOT block on
   subscriber receipt or acknowledgement of that frame.
   ```
3. [docs/specs/spec-orchestrator-status-snapshot.md:691-693,750-752,1019-1033] — **`Resync { reason: ... }` is not representable on the wire.** `SubscribeAckBody::Resync` only carries `snapshot`.
   **Fix:** Replace both `SubscribeAck::Resync { reason: "pre_v1_unsupported" }` occurrences with:
   ```md
   reject the subscribe call with `SnapshotError::Unavailable`
   before emitting any `SubscribeAck`.
   ```

### 🟡 Important
1. [docs/specs/spec-orchestrator-status-snapshot.md:737-740] — **Wrong clause label.** The documented collision risk is in clause-(b) fingerprint fallback, not clause (a) gap arithmetic.
   **Fix:** Replace lines 737-740 with:
   ```md
   **Pre-v1 cross-incarnation collision risk (documented).** Pre-v1
   clients (those subscribing with `since_boot_id = None`) MAY hit a
   low-probability false negative in clause (b)'s fingerprint-inequality
   fallback when fp-hash-collision occurs across daemon incarnations
   with identical replay-relevant state.
   ```
2. [docs/specs/spec-orchestrator-status-snapshot.md:407-411,877-882] — **ReplayCancelReason taxonomy does not match atomic co-trim.** Under Z-29, `RingEviction` and `BufferEviction` are not independently reachable during replay cancellation; only the trim-race condition is spec-legal.
   **Fix:** Replace lines 407-411 with:
   ```rust
   enum ReplayCancelReason {
       LockStepTrimRace,
   }
   ```
   And replace lines 877-882 with:
   ```md
   `PostAckFrame::ReplayCancelled { stream_seq: current_stream_seq_at_cancel,
   reason: ReplayCancelReason::LockStepTrimRace }`
   ```
3. [docs/specs/spec-orchestrator-status-snapshot.md:78-81] — **Redaction HMAC key is underspecified.** Algorithm, key size, output encoding, and lifecycle guarantees are missing.
   **Fix:** Replace lines 78-81 with:
   ```md
   - `session_id` — replace with
     `hex(HMAC-SHA-256(daemon_startup_secret_256, session_id_utf8))`.
     `daemon_startup_secret_256` MUST be a fresh 32-byte CSPRNG secret
     generated once per daemon boot, kept in memory only, never
     persisted or logged, and discarded on shutdown.
   ```
4. [docs/specs/spec-orchestrator-status-snapshot.md:924-925,931-944,1023-1026] — **`stream_seq` boot-edge semantics are ambiguous.** The spec permits `ring_oldest_seq == 0` or first published seq “typically 1”, which leaves replay/vacuous `UpToDate` behavior underspecified.
   **Fix:** Replace lines 924-925 and 931-944 with:
   ```md
   - During warm-up after the first delta
     (`0 < current_stream_seq < recent_history_ring_size`):
     `ring_oldest_seq == 1`; the index/buffer retains every emitted
     `stream_seq` from `1` through `current_stream_seq`.
   - **Z-29 boot edge case.** When `current_stream_seq == 0`, the daemon
     has emitted no deltas yet; the replay index and delta payload buffer
     are both empty. In this regime, neither clause (d) nor (d′) can
     fire. A subscriber that arrives at this moment is routed by clause
     (a), clause (P), or — if `since_stream_seq == 0` and fp/boot match —
     the vacuous arm of `UpToDate`.
   ```

## Suspected Issues Rejected as Not an Issue

- [851-888] **`since_fingerprint = None` after `ReplayCancelled`.** Conservative but coherent. It forces the full-baseline recovery path and does not create incorrect behavior.
- [868-870,883-898] **Who closes the old stream / who opens the new one.** Clear: daemon emits `ReplayCancelled` then closes that subscriber stream; subscriber re-subscribes.

## Recommended Actions
1. Rewrite T-31a/T-31b so both respect Z-29 and the no-ack stream model.
2. Remove the phantom `Resync.reason` signaling path and route refusal through `SnapshotError::Unavailable`.
3. Tighten the HMAC redaction specification.
4. Normalize `stream_seq` boot-edge wording to `0` = no deltas yet, first emitted delta = `1`.
