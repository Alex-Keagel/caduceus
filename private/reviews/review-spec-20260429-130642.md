## Findings

### 🔴 Critical
1. [§3.5 `on_worker_exit`, lines ~689-708] — The B9 dead-arm fix returns after `state.running.remove` has already removed the entry, but without clearing `claimed`/retry/token maps. If this arm is ever reached (future caller drift, refactor, or invariant break), it strands the run and violates ring/token invariants. The comment also claims `push_finished` must not run because helper already wrote — impossible if this arm is entered with `Some(entry)`.

**Fix (exact replacement text):**
```rust
        ExitReason::DaemonTerminated { .. } => {
            // Defensive fallback: expected unreachable under Z-3, but if reached
            // we must preserve terminal invariants and avoid leaked state.
            // If `terminate_and_finish` had already finalized this run, we would
            // have returned at the `state.running.remove(&run_id) == None` guard.
            state.retry_attempts.remove(&run_id);
            state.claimed.remove(&run_id);
            push_finished(state, &entry, &reason, /*final*/ true);
            state.token_totals.remove(&run_id);
            state.last_reported_tokens.remove(&run_id);
            log_diagnostic(
                "on_worker_exit handled unexpected DaemonTerminated via defensive finalize",
                run_id = &run_id,
            );
            return;
        }
```
