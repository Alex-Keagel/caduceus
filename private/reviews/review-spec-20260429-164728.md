## Findings

### 🔴 Critical
1. [docs/specs/spec-multi-repo-workspace-model.md:777-785, 1607, 1630-1632, 1663-1666] — The §3.6 step-4 bypass is keyed to "rows enqueued by §5B.2 step 4", but queue items from step 4 and step 5 share the same shape (`OrphanReclaim { slug, run_id }`) with no provenance bit. Implementers cannot deterministically apply the bypass, so the spec’s loop-prevention guarantee is unenforceable.
   **Fix:** Replace those lines with explicit queue provenance:
   ```text
   `OrphanReclaim` queue items MUST include `origin: StartupPositiveDisproof | LeafScanNoRow | EexistOrphan`.
   §5B.2 step 4 MUST enqueue `origin = StartupPositiveDisproof`; §5B.2 step 5 MUST enqueue `origin = LeafScanNoRow`.
   In §3.6 step 4, skip layered liveness probing ONLY when `reason == OrphanReclaim` AND `origin == StartupPositiveDisproof`; all other `OrphanReclaim` tasks MUST run the layered probe.
   ```

### 🟡 Important
1. [docs/specs/spec-multi-repo-workspace-model.md:1604-1607, 1615-1616] — Step 4 scope says "for every row in `Creating` or `Active`" but the normative no-pid/no-heartbeat rule includes `OrphanPending`. This is normative contradiction.
   **Fix:** Replace §5B.2 step 4 opening sentence with:
   ```text
   4. **Mark transient / reclaimable states.** For every row in `Creating`, `Active`, or `OrphanPending`, run the layered liveness probe (§3.6 step 4):
   ```
2. [docs/specs/spec-multi-repo-workspace-model.md:1293, 1587, 1712-1713] — `OrphanPending` exit semantics disagree: §4.3 says exit via `OrphanReclaim` queue → row removal, while §5B.1 and the diagram route `OrphanPending → CleaningUp` first.
   **Fix:** Replace §4.3 `OrphanPending` row with:
   ```text
   | `OrphanPending` | enters from: `Creating` (reconcile/startup), `Active` (reconcile), `CleaningUp` (cleanup-time inconclusive) | `CleaningUp` (once §3.6 step 4 positively disproves liveness), `CleanupFailed`; on successful cleanup, row removed (terminal per §4.3) | Reconcile retries once liveness can be disproved. |
   ```
3. [docs/specs/spec-multi-repo-workspace-model.md:1138-1141, 1884; docs/specs/spec-orchestrator-status-snapshot.md:1277-1283] — Cross-spec contract is incomplete: spec #4 states `WorkspaceMeta.status: WorkspaceStatus` aliasing spec #3 status, but this spec defines no `WorkspaceStatus` alias and #4 cross-reference omits status.
   **Fix:** Add to §4 Data shapes type aliases:
   ```rust
   type WorkspaceStatus = Status;           // alias consumed by spec #4 WorkspaceMeta.status.
   ```
   and replace §9 row `#4 Snapshot` with:
   ```text
   | **#4 Snapshot** | reads | `Workspace.path`, `Workspace.repo_coordinate`, `Workspace.created_at`, and `WorkspaceStatus` (alias of this spec’s registry `status`) appear in the per-row snapshot (`WorkspaceMeta.status` in spec #4 §4.2). The runs panel (spec #8) renders these. |
   ```
