## Findings

### 🔴 Critical
1. [Lines 276-276, §3.3] — `run_id` is required to “pass the same regex,” but no run-id regex is defined there; the nearest regex is the slug regex, which is wrong for `sanitize_run_id` output. **Fix:**  
   ```text
   3. Assert `run_id` satisfies all §3.2 output constraints: every character is in `[A-Za-z0-9._-]`; the value is not `.`, `..`, empty, or any string matching `^\.+$`; and the value does not contain `..` as a substring. Otherwise MUST return `InvalidRunId`.
   ```

2. [Lines 432-432, §3.5 step 4] — Step 4 is dead/conflicting lock logic after step 1.3 already acquired or refused the per-slug guard. A literal implementation may double-lock and deadlock. **Fix:**  
   ```text
   4. *(No operation. Shared-repo lock conflict is handled exclusively by step 1.3's try-lock on the per-slug guard. Control reaching this point guarantees the per-slug guard is already held for this invocation.)*
   ```

3. [Lines 1146-1149, §3.6 step 9] — Row deletion is a registry mutation, but the step does not re-acquire the registry-wide mutex. That contradicts the rest of the spec's mutation discipline. **Fix:**  
   ```text
   9. **Remove registry entry, release locks (Z-14: explicit release order).** Briefly re-acquire the registry-wide mutex; delete the row keyed by `workspace_id`; release the registry-wide mutex. The subsequent lock release order is **normative** (the REVERSE of acquire order `registry-wide → per-slug → per-workspace`):
   ```

4. [Lines 875-883, §3.6 step 1] — The step says “Acquire registry write lock for this workspace” and then calls it “A workspace-level lock,” but never explicitly performs the normal-path `Active → CleaningUp` transition. This is contradictory and under-specifies cleanup state transitions. **Fix:**  
   ```text
   1. **Acquire per-workspace lock; transition to `CleaningUp`.** Acquire the per-workspace lock keyed by `workspace_id`; concurrent `cleanup` calls on different workspaces MAY proceed in parallel. Briefly acquire the registry-wide mutex; if `registry_row = Some(row)`, transition the row to `Status::CleaningUp`; release the registry-wide mutex. Lock acquisition order remains `registry-wide → per-slug → per-workspace`; release order remains the reverse. See §4.5 for the canonical statement.
   ```

5. [Lines 1703-1719, §5A.5] — The ownership handoff only chowns the leaf directory entry. Files created by `after_create` (for example `git clone`) remain daemon-owned, so the runner may be unable to edit the repository. **Fix:** insert after line 1719:  
   ```text
   **Content ownership (normative).** The `fchownat` above transfers ownership of the leaf directory entry only. Any files or directories created under the leaf by `after_create` MUST also be writable by `runner_uid:runner_gid` before `create_workspace` returns. Implementations MUST satisfy this by either: (a) performing a recursive fd-anchored ownership transfer of leaf contents after the directory handoff, or (b) requiring `after_create` to complete the equivalent transfer before exit. An implementation that leaves repository contents daemon-owned is non-conformant.
   ```

### 🟡 Important
1. [Lines 891-897, §3.6 step 3] — “short-circuit to cleanup-cleared” is undefined. A first-time implementer cannot tell whether that means row delete, status change, or silent success. **Fix:**  
   ```text
   2. `slug_fd ← openat(workspace_root_fd, slug, O_DIRECTORY | O_NOFOLLOW | O_CLOEXEC)`.
      On `ENOENT`, classify the row as `OrphanedNoSlug` and short-circuit directly to step 9 (terminal success path: row removal if `registry_row = Some(_)`, otherwise no registry mutation). Steps 4–8 MUST NOT execute.
   3. `leaf_fd ← openat(slug_fd, sanitize_run_id(run_id), O_DIRECTORY | O_NOFOLLOW | O_CLOEXEC)`.
      On `ENOENT` or `ELOOP` (symlink), classify the row as `OrphanedNoLeaf` and short-circuit directly to step 9 under the same terminal-success rules. Steps 4–8 MUST NOT execute.
   ```

2. [Lines 415-417, §3.5 step 1.4 precondition] — “control transfers from step 1.2 directly to step 5b” reads as if steps 2–5a are skipped. That is dangerous in a filesystem-safety algorithm. **Fix:**  
   ```text
   step 1.4 inserts a `Creating` placeholder ONLY when step 1.2 found no matching row; for `{CleanupFailed, OrphanPending}` rows, step 1.4 is skipped (no placeholder insertion), but steps 1.5 through 5a proceed unchanged. At step 5b, if `mkdirat` returns `EEXIST`, the carried-forward row's status is used as the reclaim discriminator.
   ```

3. [Lines 1619-1623, §5A.3] — The normative fd table omits `O_CLOEXEC` from `workspace_root_fd`, `slug_fd`, and `leaf_fd`. A table-following implementation can leak privileged fds into hook subprocesses. **Fix:**  
   ```text
   | Open `workspace_root_fd` | daemon startup | `O_DIRECTORY \| O_NOFOLLOW \| O_CLOEXEC` |
   | Open `slug_fd` (create) | §3.5 step 5b | `openat(workspace_root_fd, slug, O_DIRECTORY \| O_NOFOLLOW \| O_CLOEXEC)` |
   | Open `leaf_fd` (create) | §3.5 step 5c | `openat(slug_fd, sanitize_run_id(run_id), O_DIRECTORY \| O_NOFOLLOW \| O_CLOEXEC)` |
   | Open `slug_fd` (cleanup) | §3.6 step 3 | `openat(workspace_root_fd, slug, O_DIRECTORY \| O_NOFOLLOW \| O_CLOEXEC)` |
   | Open `leaf_fd` (cleanup) | §3.6 step 3 | `openat(slug_fd, sanitize_run_id(run_id), O_DIRECTORY \| O_NOFOLLOW \| O_CLOEXEC)` |
   ```

4. [Lines 1643-1650, §5A.4] — UID separation is only SHOULD-level even though heartbeat-forge resistance depends on it. **Fix:**  
   ```text
   - The daemon MUST run as a dedicated uid distinct from any
     runner uid.
   - Runners MUST run as a uid distinct from the daemon, ideally
     one per workspace (or one per workflow tier) so heartbeat-file
     permissions provide meaningful uid-scoped isolation.
   ```

5. [Lines 467-472, §3.5 step 5b; lines 1364-1371, §4.2] — Create-side slug-fd reassertion assumes `row.parent_dev_ino` exists, but legacy rows are explicitly allowed to carry `None`. **Fix:** append after line 472:  
   ```text
   **Legacy null exception.** If the carried-forward row from step 1.2 has `parent_dev_ino == None` (legacy row, per §4.2 / Appendix D), this assertion is skipped for the current create attempt and the daemon MUST populate `parent_dev_ino` with the just-`fstat`'d `(st_dev, st_ino)` tuple in the §3.5 step 9 registry update, logging `parent_dev_ino_tofu_populated`.
   ```

6. [Lines 266-266, §3.2] — The worked example says spaces are rejected by “rule 1 after trim,” but the actual rejection is rule 4 after sanitize+trim. **Fix:**  
   ```text
   | `   ` | rejected (rule 4) | empty after sanitize+trim |
   ```
