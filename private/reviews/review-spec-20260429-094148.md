## Findings

### 🔴 Critical
1. [§4.2.1] Read-only spec defines write-path truncation (`before storing it in RetryEntry`). **Fix:** Replace the truncation bullet with: `- Spec #1 owns ingestion-time truncation of RetryEntry.error_message. Spec #4 is read-only: it MUST NOT mutate RetryEntry. When projecting RetryRow or retry-bearing SnapshotDelta, the daemon MUST enforce retry_error_max_bytes on the copied value as a defensive clamp only.`
2. [§3.1 / §4.1] `age` becomes enormous if `started_at` clamps to `UNIX_EPOCH`. **Fix:** Replace `age: Duration,                // runtime_now − started_at, computed at projection.` with `age: Duration,                // mono_now.saturating_duration_since(RunningEntry.started_at); MUST NOT be recomputed from projected started_at.` Add: `If project(started_at) clamps to SystemTime::UNIX_EPOCH, RunRow.age is still computed from the source Instant and remains monotonic/correct.`
3. [§4.8] `RateLimitBlob.raw` is unbounded. **Fix:** Replace `raw:                  Option<JsonValue>,         // pass-through for non-standard fields.` with `raw:                  Option<JsonValue>,         // included only if canonical JSON UTF-8 size <= rate_limit_raw_max_bytes (default 4096) and nesting depth <= 8; otherwise omitted.` Add: `The daemon MUST apply the same bound before snapshot inclusion and delta emission.`
4. [§1.2] Untrusted-transport redaction omits `error_message`, `prompt_hash_trail`, `hook_log`, `RateLimitBlob.raw`. **Fix:** Replace the redaction sentence with: `On any other transport, the daemon MUST redact pid, workspace_path, event_log_tail, RetryRow.error_message, RunDetail.prompt_hash_trail, hook_log, and RateLimitBlob.raw from all SnapshotResponse payloads and SnapshotDelta emissions before publishing.`
5. [§3.2 / §4.9 / §6] `BudgetTooSmall` is inconsistent with the defined RPC surface and current tests. **Fix:** Precise action: either delete `BudgetTooSmall` from `SnapshotError`, or add `SnapshotRequestOptions { snapshot_timeout_ms: u32 }` to `dispatch_snapshot_request`, require `BudgetTooSmall` before calling `build_snapshot`, and add a conformance test for that path.
6. [§4.3 / §3.3] `AggregateUpdated` omits `agents_max`, so ceiling drops cannot be reconstructed from deltas while fingerprint rules still depend on it. **Fix:** Replace `AggregateUpdated { ... agents_used: u32, next_poll_at: Option<SystemTime>, snapshot_fingerprint: SnapshotFingerprint }` with `AggregateUpdated { ... agents_used: u32, agents_max: u32, next_poll_at: Option<SystemTime>, snapshot_fingerprint: SnapshotFingerprint }` and replace the hot-reload note with: `agents_used == running.len() + disconnected.len() MUST hold on every snapshot and AggregateUpdated delta. During a hot-reload that lowers max_concurrency from N to M < N, the only relaxed invariant is agents_used <= agents_max: agents_used MAY temporarily exceed agents_max until natural drain reduces running.len() to M, but the daemon MUST NOT fabricate a lower agents_used, and subscribers MUST learn the new agents_max via the same AggregateUpdated that changes the fingerprint.`

### 🟡 Important

[iter-4 Y-* vs iter-5 Z-*] Resolution is partial, not complete; Y-5 remains open. **Fix:** Add appendix text: `Y-4 -> resolved by §4.5 ring ownership; Y-5 -> unresolved pending §4.2.1 ownership + transport redaction fix; Y-10 -> resolved by T-17; Y-11 -> resolved by §3.4 input/clauses; Y-13 -> resolved by §4.6.1 canonical encoding.`
2. [§4.1.1] `RunStatus::Retrying` is declared but unreachable in `RunRow`. **Fix:** Replace the enum with: `enum RunStatus { Running, Disconnected }` and add: `` `Retrying` is represented only by `AggregateSnapshot.retrying` / `RetryRow` and MUST NOT appear in RunRow.status. ``
3. [§3.4.1 / §1.2 / §7] Wire-field ordering is prescribed in a transport-neutral spec. **Fix:** Replace the field-order paragraph with: `For positional encodings, the field order is version, boot_id, fingerprint, stream_seq, body. For schema/tag-based encodings, field order is not normative; the concrete transport ADR MUST define decoding such that version is validated before body is acted upon.`
4. [§3.5.1] `subscribe_ack_max_ms ≥ snapshot_timeout_ms` is too weak without an effective floor/headroom rule. **Fix:** Replace the constraint sentence with: `Because Resync includes build_snapshot time, implementations MUST ensure subscribe_ack_max_ms >= effective_snapshot_timeout_ms used on the subscribe path after minimum-budget enforcement, and effective_snapshot_timeout_ms MUST be >= minimum_ms.`
5. [§4.1] `parent_run_id` reserved-v1 rejection lacks test coverage. **Fix:** Add tests: `T-27: v1 producer emits parent_run_id=None` and `T-28: v1 consumer rejects parent_run_id=Some(_) as protocol error.`
6. [§6] Missing `BudgetTooSmall` conformance test. **Fix:** Add `T-26: snapshot_timeout_ms below minimum returns BudgetTooSmall{requested_ms, minimum_ms} and no snapshot is built.`

## Recommended Actions
1. Resolve the §4.2.1 ownership contradiction by moving write-path truncation entirely into spec #1 or explicitly splitting ingestion-time vs projection-time clamps.
2. Bound all agent-controlled payloads symmetrically (`error_message`, `RateLimitBlob.raw`, RunDetail tails/hashes/logs).
3. Fix RPC/test surface mismatches (`BudgetTooSmall`, `parent_run_id`, `agents_max` delta visibility).
4. Clean up dead or contradictory transport/status machinery before implementation diverges.
