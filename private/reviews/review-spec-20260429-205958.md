2. [docs/specs/spec-multi-repo-workspace-model.md:1992] — T-16 still over-permits loser outcomes. In the stated scenario (two concurrent `create_workspace` calls for the same `(slug, run_id)`), the registry-wide critical section plus step 1.4 placeholder insertion force the loser onto the `Status::Creating` / `WorkspaceBusy` path when the namespace starts clean. `WorkspaceAlreadyExists` and `WorkspaceBusyOrReclaiming` require a pre-existing duplicate leaf or reclaimable stale state, which this test does not set up. **Fix:** Replace the entire bullet with: `- T-16: Two concurrent \`create_workspace\` calls with the same \`(slug, run_id)\`, starting from a clean namespace (no pre-existing row and no pre-existing leaf), ⇒ exactly one succeeds; the loser receives \`Error::WorkspaceBusy\` via §3.5 step 1.2's \`Status::Creating\` branch. \`Error::WorkspaceAlreadyExists\` and \`Error::WorkspaceBusyOrReclaiming\` are covered by separate tests that begin with a pre-existing duplicate leaf or reclaimable stale state. No partial leaves are left behind.`
