4. [§3.7 Lock guard contract, line 1204] Per-slug guard lifetime across create→cleanup is unspecified. **Fix:**

```md
**Lock guard contract:** The returned `LockGuard` MUST be released on workspace cleanup
(§3.6 step 9) **and** on `create_workspace` failure-rollback (§3.5 step 10). Lock leaks
are a high-severity bug: the next Run on the same repo hangs indefinitely.

**Storage across create→cleanup (normative).** After `create_workspace` returns
successfully (step 9), the per-slug guard is no longer on the call stack. The daemon
MUST store it in daemon-process-scoped, in-memory state keyed by `repo_coordinate.slug`
(e.g., a `HashMap<RepoSlug, Arc<Mutex<LockGuard>>>` in the workspace manager). The guard
persists in that store for the entire Run lifetime. `cleanup_workspace` MUST retrieve the
stored guard by slug and hold it for §3.6 steps 2–9; it MUST fail with a programmer-error
panic or `CRITICAL` log if no stored guard is found for that slug on the normal
(non-OrphanReclaim) cleanup path. The `OrphanReclaim` background sweeper MUST re-acquire
the per-slug guard fresh (Wait discipline) because no successful `create_workspace` placed
a guard in the store for that workspace. In-memory guards are cleared on daemon restart;
the startup recovery procedure (§5B.2) re-acquires no guards — it routes everything
through the reconcile/OrphanReclaim queue which re-acquires fresh.
```

8. [§5B.2 step 7, lines 1915-1963] Canonical bypass scope is over-expanded and repeated. **Fix:**

```md
**Canonical bypass scope (normative; single source of truth).**
For every `OrphanReclaim { slug, run_id }` queue entry — regardless
of enqueue source (§3.5 step 5b, §5B.2 steps 4/5/7, or startup recovery) —
the §3.6 re-entry skips ONLY step 4 (layered liveness probe) and retains
steps 2, 3, 5, 5a, 6, 7, 8, 9 unchanged.

Rationale: every enqueue source either (a) attaches a fresh
positive-disproof verdict at enqueue time, (b) has no runner record to
probe, or (c) represents a deterministic failure with no live runner.
Re-probing at drain time adds latency and risks false `Inconclusive`
re-classification.
```
