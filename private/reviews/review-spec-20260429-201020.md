## Findings

### 🔴 Critical
1. [spec-orchestrator-status-snapshot.md:450-473, 525-545, 673-728, 929-960] — `UpToDate` still loses fingerprint-excluded deltas. Counterexample: subscriber at `s_c` misses only `AggregateUpdated` / token-only deltas; `current_fingerprint == last_known_fingerprint`, so vacuous `UpToDate` advances cursor to `current_stream_seq` and permanently drops the missed excluded-field updates. **Fix:** change clause (d) to trigger on same-boot, in-window, `last_known_fingerprint == fingerprint_at(s_c)`, and `s_c < current_stream_seq` (not `last_known_fingerprint != current_fingerprint`). Vacuous `UpToDate` must be restricted to the no-gap case. Add a test where only fingerprint-excluded deltas were missed and replay still occurs.
2. [spec-orchestrator-status-snapshot.md:440-448, 731-750, 840-863] — replay-mode cancellation still requires an impossible in-stream `Resync`. The stream is defined as initial `SubscribeAck` followed by `SnapshotDelta`; there is no legal mid-stream `Resync` frame. **Fix:** replace replay-mode step 4 with: if replay becomes impossible, terminate the subscribe stream with `SnapshotError::Unavailable`; subscriber immediately re-subscribes with `since_fingerprint=None`, `since_stream_seq=None`, `since_boot_id=Some(last_ack.boot_id)`, routing deterministically to clause (c). Alternatively, explicitly widen the stream grammar to allow a second `SubscribeAck`/`Resync` frame.

### 🟡 Important
1. [spec-orchestrator-status-snapshot.md:693-706, 770-785] — delta-payload retention and Z-29 still contradict each other, and Z-29's span bound is impossible during warm-up. The payload paragraph retains `(current-size, current]`, while Z-29 requires both structures to contain `[ring_oldest_seq, current_stream_seq]`; also `current_stream_seq - ring_oldest_seq >= recent_history_ring_size` cannot hold before `recent_history_ring_size` deltas have been emitted in the current boot. **Fix:** make the retained window explicit as `[max(0, current_stream_seq - recent_history_ring_size), current_stream_seq]` in both structures, and define warm-up separately: if `current_stream_seq < recent_history_ring_size`, then `ring_oldest_seq = 0`; otherwise `current_stream_seq - ring_oldest_seq = recent_history_ring_size`.
2. [spec-orchestrator-status-snapshot.md:620-635, 755-766] — the six-clause closure is still not exhaustive for pre-v1 `since_boot_id=None` in the synthetic collision case `last_known_fingerprint == current_fingerprint != fingerprint_at(s_c)` with in-window `s_c`. Clause (b) fallback does not fire because current fingerprints match; clauses (d)/(d′) as written require `since_boot_id == daemon.boot_id`; vacuous `UpToDate` is then selected incorrectly. **Fix:** allow clauses (d) and (d′) to evaluate when `since_boot_id` is omitted but `since_stream_seq` is in-window; use `fingerprint_at(s_c)` to distinguish replay vs resync. Add a pre-v1 version of T-30b.
3. [spec-orchestrator-status-snapshot.md:745-750, 1081-1086, 1978-2054] — DoS-clamp replay cancellation is not proven by the test inventory. T-25 only covers `RunDetail` clamp; T-20/T-21 cover generic backpressure; none force ring rotation during clause-(d) replay. **Fix:** add a test that starts clause-(d) replay, rotates the retained window mid-replay, and proves the required recovery path and no live-delta overtaking.

## Recommended Actions
1. Fix the clause-(d)/vacuous-`UpToDate` split so replay is driven by gap existence, not fingerprint change.
2. Replace or formally define the replay-cancel recovery frame.
3. Re-spec Z-29 with a single warm-up-aware retained-window definition.
4. Add tests for excluded-field-only gaps, replay cancellation under ring rotation, and pre-v1 collision closure.
