## Findings

### 🔴 Critical
1. [L876-L890] — `on_retry_timer` correctly re-classifies before concurrency dispatch, but the new Terminal/Neither arms are not executable as written. `cleanup_after_terminal(state, &run.id)` is undefined in this spec, and both arms omit `state.claimed.remove(&run.id)` / `state.dispatch_defer_attempts.remove(&run.id)`, leaking per-run state on exactly the path that is supposed to clean it up.  
   **Fix:** Replace the current `match class` block with:

   ```rust
       // Re-classify before any concurrency check or dispatch. The state of
       // the run may have changed between scheduling this timer and firing it.
       // The prior `RunningEntry` has already been removed by `on_worker_exit`,
       // so `terminate_and_finish` cannot be reused here: its
       // `state.running.remove(&run_id)` guard would early-return without
       // releasing `claimed` or `dispatch_defer_attempts`.
       let class = classify_run(state, &run);
       match class {
           TrackerClass::Terminal => {
               cleanup_workspace(&run.id, state).await;
               state.claimed.remove(&run.id);
               state.retry_attempts.remove(&run.id);
               state.dispatch_defer_attempts.remove(&run.id);
               state.token_totals.remove(&run.id);
               state.last_reported_tokens.remove(&run.id);
               log_diagnostic(
                   "on_retry_timer dropped run after Terminal reclassification",
                   run_id = &run.id,
               );
               return;
           }
           TrackerClass::Neither => {
               state.claimed.remove(&run.id);
               state.retry_attempts.remove(&run.id);
               state.dispatch_defer_attempts.remove(&run.id);
               state.token_totals.remove(&run.id);
               state.last_reported_tokens.remove(&run.id);
               log_diagnostic(
                   "on_retry_timer dropped run after Neither reclassification",
                   run_id = &run.id,
               );
               return;
           }
           TrackerClass::Active => {
               // Fall through to slot-pressure check and dispatch.
           }
       }
   ```

   **Fix:** Replace the paragraph beginning `token-drain site (` with:

   ```md
   token-drain site. The canonical drain sites are identified by branch name,
   not by line number: `terminate_and_finish` (§3.1); `on_worker_exit`'s
   defensive `DaemonTerminated` arm (§3.5); `on_retry_timer`'s "run vanished
   from WorkSource" branch (§3.5); `on_retry_timer`'s Terminal
   reclassification branch (§3.5); `on_retry_timer`'s Neither
   reclassification branch (§3.5); and `on_retry_timer`'s dispatch-defer

   `state.last_reported_tokens` together. The four cascade call sites (§3.2
   ```

### 🟡 Important
1. [L124-L127 vs. L706-L711] — `ClaimedSet` is defined as “within a single tick”, but later the spec explicitly keeps claims alive across retry windows. That is a real contradiction.  
   **Fix:** Replace L124-L127 with:

   ```md
   - **ClaimedSet** — the set of `RunId`s currently owned by the orchestrator
     for dispatch/retry lifecycle control. A claim is created on successful
     dispatch and persists across retry scheduling windows; it is cleared only
     by terminal finalize, reconcile-to-terminal/neither, retry abandonment,
     or explicit stale-run cleanup.
   ```

2. [L1503-L1511, L724] — The spec persists raw failure strings into `RetryEntry.error_message` and projects them to the snapshot surface without any redaction rule.  
   **Fix:** Replace the field comment with:

   ```rust
   /// Diagnostic text from the failure that produced this retry.
   /// This field MUST be redacted before persistence or publication.
   /// It MUST NOT include secrets, tokens, credentials, environment-variable
   /// values, or absolute local paths unless the sink is explicitly restricted
   /// to operator-only diagnostics.
   error_message:    Option<String>,
   ```

   and replace L724 with:

   ```rust
               Some(redact_retry_error(error)))
   ```

3. [L532-L535] — `agents SHOULD emit progress events ...` is guidance to another spec / component, not an enforceable contract here.  
   **Fix:** Replace the bullet with:

   ```md
   - **Stall sweep false positive.** A long-running tool (e.g. a multi-minute
     test runner) that emits no events can be killed. This spec does not impose
     an agent-side heartbeat requirement; any heartbeat contract is owned by
     spec #2. Until spec #2 defines one, treat this as a known limitation. See
     §8.4.
   ```

4. [L2303-L2311] — The hot-reload section says the question is “open” and then immediately gives a MUST-level answer.  
   **Fix:** Replace L2303-L2311 with:

   ```md
   Spec #6 owns the normative hot-reload policy. This spec fixes only two
   points: `validate_dispatch_config` re-runs at the top of every tick (§3.2
   step 2), and if a reload lowers `max_concurrency` from `N` to `M < N`, the
   daemon MUST NOT terminate live attempts solely to reach the new ceiling; it
   MUST stop admitting new attempts until `running.len() <= M`.
   ```

5. [L341, L711, L1386, L1524, L2221, L2437] — unresolved / stale anchors (`X-11`, `§6`, `X-3 / X-5`) remain.
