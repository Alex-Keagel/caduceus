## Findings

### 🔴 Critical

1. **[Lines 430–437, 1247–1253, 1269–1282, 1984–1989]** — malformed handshake payload has no normative behavior; only “missing handshake” fallback is defined.

   **Fix (exact replacement text):**

   Replace line 1249 sentence with:

   > `If the handshake is missing **or malformed** (kind == "handshake" but payload.capabilities is absent, non-object, or fails type validation), the daemon executes the T-4 fallback most-restrictive policy described below.`

   Add this sentence after line 436 in §3.2:

   > `If parse_capabilities(event.payload) fails validation, the runner MUST emit { kind: "malformed_handshake", run_id, seq: event.seq }, set runner.capabilities = Capabilities::most_restrictive(), set handshake_seen = true, and continue processing without stop_cascade (same fallback semantics as T-4).`

2. **[Lines 987–991 vs §3.2 lines 305–567]** — schema requires `run_id` match, but §3.2 never normatively checks `event.run_id == runner.run_id`; cross-run injection is possible if a vendor emits wrong run_id.

   **Fix (exact replacement text):**

   Insert after parse success (after line 325):

   > `if event.run_id != runner.run_id:`
   > `    emit_event(daemon_event_channel, { kind: "protocol_violation", run_id: runner.run_id, reason: "run_id_mismatch", event_run_id: event.run_id, seq: event.seq })`
   > `    stop_cascade(runner, reason = "run_id_mismatch", grace_period_ms = GraceWindow)`
   > `    return`

3. **[Lines 89–91, 1408–1453]** — per-Run `runner_seq` durability assumes serialized attempts, but no explicit “single active attempt per run_id” requirement; concurrent attempts can violate gap-free counter semantics.

   **Fix (exact replacement text):**

   Add under §4.4 Normative rules (after rule 3):

   > `3a. For a given run_id, at most one RunAttempt MAY be Running at any time. The orchestrator MUST NOT spawn attempt N+1 until attempt N has reached terminal state and the prior RunnerProcess is reaped. This preserves single-writer ownership of runner_seq for that run_id.`

4. **[Lines 436–470]** — capability mutation happens before handshake consistency checks; transient publication can race readers and violate fail-closed intent.

   **Fix (exact replacement text):**

   Replace lines 436–470 block header with:

   > `parsed_caps = parse_capabilities(event.payload)`
   > `// validate parsed_caps against env + C2 constraints before publication`
   > `...existing validation checks using parsed_caps...`
   > `runner.capabilities = parsed_caps`
   > `handshake_seen = true`

5. **[Lines 1135–1142 vs §3.2 305–567]** — Z-11 says unknown kind MUST protocol-violate, but §3.2 pseudocode does not explicitly show unknown-kind rejection path; behavior is implicit/undefined.

   **Fix (exact replacement text):**

   Insert after parse success (or as part of parser contract):

   > `if event.kind not in ALLOWED_AGENT_TO_DAEMON_KINDS:`
   > `    emit_event(daemon_event_channel, { kind: "protocol_violation", run_id: runner.run_id, reason: "unknown_message_kind", offending_kind: event.kind, seq: event.seq })`
   > `    stop_cascade(runner, reason = "unknown_message_kind", grace_period_ms = GraceWindow)`
   > `    return`
