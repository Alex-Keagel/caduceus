### 🟡 Important
1. [1026-1034 vs. 986-991] — normative mandatory-frame rule is narrower than the pseudocode preamble, leaving ambiguity about which inbound kinds are non-droppable.
   **Fix:**
   ```text
   4. The runner MUST NOT drop, under any saturation condition, any inbound frame other than `turn_event`. This mandatory set includes `turn_start`, `turn_end`, `stage_transition`, `run_complete`, `cancel_ack`, `heartbeat`, `tool_use_request`, `permission_elevation_request`, `token_update`, `log`, `error`, `exit`, and `cross_run_handoff`. `handshake` is excluded because §3.2 consumes it before steady-state queueing; reattach is excluded because it is an engine→daemon RPC (§4.5).
   ```

2. [1635-1639] — broken internal cross-reference `§4.6.1 Z-9`; this document only goes to §4.5.
   **Fix:** Replace line 1639 with `boot_id: Uuid, // 16-byte raw per spec #4 §3.4 SubscribeAck / Z-9`

3. [770, 775, 2077-2078] — defaults are stated as lower bounds (`≥ 100 ms`, `≥ 150 ms`) but test arithmetic assumes exact defaults.
   **Fix:**
   - `Default **100 ms**, configurable via `shutdown_enqueue_budget_ms`.`
   - `Default **150 ms**, configurable via `sigkill_reap_budget_ms`.`

4. [835-846, 1384] — ACP is said to require explicit spawn-time negotiation, but the selection mechanism is not specified in this spec.
   **Fix:**
   ```text
   **ACP selection (normative).** ACP is selected at spawn time by the daemon when `workflow.protocol == "acp"` (or equivalent workflow config field — the precise key is owned by spec #1). If ACP is not explicitly selected at spawn, the runner uses JSONL; `supports_acp` in handshake remains informational only.
   ```

5. [2305-2307] — heading still says “Open questions” even though §8 contains closed normative decisions.
   **Fix:** Replace line 2305 with `## 8. Open questions and resolved decisions (v1)`
