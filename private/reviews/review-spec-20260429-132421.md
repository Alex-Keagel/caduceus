### 🟡 Important

1. [docs/specs/spec-orchestrator-status-snapshot.md:492-503] — The “First-delta rules (strict split, normative summary)” bullets use abbreviated `subscribe(...)` forms that omit `channel` everywhere and omit `since_boot_id` in the very summary that distinguishes resync cases. Line 498 is the sharpest case because it mentions “`boot_id` differs” while showing only `subscribe(since_stream_seq = Some(s_c))`, which can be skimmed as if `since_boot_id` is irrelevant to that path.  
   **Fix:** Replace the three bullets with:
   ```md
   - `subscribe(channel, since_fingerprint = Some(_), since_stream_seq = Some(s_c), since_boot_id = Some(_) | None)`
     where `current_stream_seq − s_c ≤ recent_history_ring_size` AND `boot_id` is unchanged AND no force-resync clause fires
     ⇒ **`UpToDate`**: subscriber retains its local snapshot; the daemon replays buffered deltas in `(s_c, current_stream_seq]` from the broadcast channel followed by live deltas.
   - `subscribe(channel, since_fingerprint = Some(_) | None, since_stream_seq = Some(s_c) | None, since_boot_id = Some(_) | None)`
     where the gap exceeds the ring OR `boot_id` differs OR the force-resync clauses below fire
     ⇒ **`Resync { snapshot, stream_seq }`**: subscriber discards local state; live-only deltas after that, no replay window.
   - `subscribe(channel, since_fingerprint = None, since_stream_seq = Some(_) | None, since_boot_id = Some(_) | None)`
     ⇒ **`Resync { snapshot, stream_seq }`** unconditionally (clause (c) below); live deltas thereafter.
   ```

2. [docs/specs/spec-orchestrator-status-snapshot.md:705-706] — The boot_id-mismatch hard-reset procedure prescribes a defensive re-subscribe with `since_fingerprint = None` and `since_stream_seq = None`, but leaves `since_boot_id` unstated. Clause (c) still forces resync, so this is not a correctness bug, but it leaves a normative gap in the one place the doc gives a concrete fallback call recipe.  
   **Fix:** Replace lines 705-706 with:
   ```md
   defensively close the subscribe stream and re-subscribe with
   `since_fingerprint = None`, `since_stream_seq = None`, and
   `since_boot_id = None` (clause (c) of §3.4);
   ```
