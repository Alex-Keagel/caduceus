## Findings

### 🔴 Critical
1. [118-121, 2293-2352] — `ReplayCancelReason::RingEviction` and `::LockStepTrimRace` still overlap. T-31 describes lock-step trim during replay as `RingEviction`, while T-31b describes lock-step trim racing replay as `LockStepTrimRace`. **Fix:** make `LockStepTrimRace` the proactive pre-commit path and `RingEviction` the reactive already-evicted fallback, or collapse them into one reason.
2. [698-703, 2232-2244, 925-951, 977-1001] — Clause labels / boot-edge logic are still inconsistent. `(d′)` is still called `(d)` in clause-(b) independence text and T-29; boot `current_stream_seq == 0` does not define the same-boot `s_c == 0` + fp mismatch path, so the six-clause set is not actually total there. **Fix:** rename those references to `(d′)` and make the boot-edge block route every non-vacuous empty-index case to `Resync`.
3. [384-390, 1474-1478, 1641-1653, 1918-1923] — `AggregateUpdated` omits `agents_max`, but the fingerprint explicitly depends on `agents_max`. A config hot-reload can therefore change the fingerprint and aggregate snapshot without any replayable delta carrying the changed field. **Fix:** add `agents_max: u32` to `AggregateUpdated`.
