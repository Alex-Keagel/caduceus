## Five-fix re-verification

1. **SubscribeFrame wrapper stream type** — **Resolved.**  
   Glossary (`PostAckFrame` / `SubscribeFrame`), enum, function signature, and stream-protocol prose now agree on `Stream<SubscribeFrame>`. No new contradiction found.

2. **Z-29 boot edge** — **Mostly resolved, but not cleanly.**  
   The doc now correctly blocks clauses (d)/(d′) at `current_stream_seq == 0`. But it still routes boot-edge cases through clause (P) even though `ring_oldest_seq := min(stream_seq)` is undefined when the replay index is empty. That makes the boot-edge logic internally brittle.

3. **pre-v1 collision wording** — **Not fully resolved.**  
   The core issue remains: §3.4 says clauses (d)/(d′) **MAY** fire when `since_boot_id = None`, while T-10-pre-v1 / T-30b-pre-v1 assert they **do** fire. That is still a spec/test contradiction.

4. **Clause (c) closure priority** — **Partially resolved.**  
   The priority ladder is present and correctly ordered, but other prose still says `since_fingerprint = None` routes to `Resync` "unconditionally" / "always falls through to clause (c)", which contradicts `(a) > (P) > (b) > (c)` and the requirement to evaluate overlapping predicates coherently.

5. **Glossary/tests additions** — **Partially resolved, with one new contradiction.**  
   The glossary additions are good. The tests still leave a semantic gap for `ReplayCancelled.stream_seq`. Worse, T-31b adds a new contradiction by requiring trim to wait for subscriber receipt of the cancel frame, which conflicts with §3.3's no-back-pressure/drop-on-full rule.

## Findings

### 🔴 Critical
1. [§3.4 L722-L725; §6 T-10-pre-v1 L2264-L2274; T-30b-pre-v1 L2276-L2282] — Pre-v1 same-boot replay/divergence remains non-deterministic in prose (`MAY`) but deterministic in tests.  
   **Fix:** Replace the bullet under **Pre-v1 boot_id absence (normative)** with:
   > - Clauses (d) and (d′) MUST fire if `s_c` is in-window and the fingerprint predicate resolves per their normal triggers; the daemon MUST treat `since_boot_id == None` as boot-match-assumed for same-boot evaluation. Tests T-10-pre-v1 and T-30b-pre-v1 cover these cases.

2. [§3.4 L596-L597; L771-L772; §3.4.1 L1050-L1053; closure rule L991-L994] — Clause (c) is still described as unconditional / always-falls-through even though higher-priority clauses subsume it.  
   **Fix:** Replace:
   > `⇒ Resync { snapshot, stream_seq } unconditionally (clause (c) below); live deltas thereafter.`
   with:
   > `⇒ Resync { snapshot, stream_seq } always; attribution is to clause (c) only when no higher-priority clause (a), (P), or (b) is also true; live deltas thereafter.`
   
   Replace:
   > `SubscribeAck::Resync { … }` unconditionally; the daemon MUST NOT serve `UpToDate` for a `None` fingerprint, even on a quiescent channel.
   with:
   > The selected wire outcome is always `SubscribeAck::Resync { … }`; when `since_fingerprint = None`, clause attribution is to (c) only if no higher-priority clause `(a)`, `(P)`, or `(b)` is also true. The daemon MUST NOT serve `UpToDate` for a `None` fingerprint, even on a quiescent channel.
   
   Replace:
   > `since_fingerprint = None` always falls through to clause (c)
   with:
   > `since_fingerprint = None` forces a `Resync` outcome; clause attribution is to (c) only when no higher-priority force-resync clause is also true

3. [§6 T-31b L2315-L2320 vs §3.3 L444-L445] — T-31b invents per-subscriber back-pressure on trim: "trim itself MUST NOT proceed until the subscriber receives the cancel frame". That contradicts the spec's explicit no-back-pressure/drop-on-full rule and Z-29's actual lock-step requirement (index vs payload buffer, not subscriber I/O).  
   **Fix:** Replace the final sentence of T-31b with:
   > The replay-index/payload-buffer trim MUST be atomic with respect to each other (per Z-29 sub-invariant 3) and MUST NOT be gated on per-subscriber wire delivery. The daemon emits exactly one `PostAckFrame::ReplayCancelled { stream_seq, reason: ReplayCancelReason::LockStepTrimRace }` to the affected subscriber if it can be enqueued, then closes that subscriber's send queue; the trim path MUST NOT block on subscriber I/O.

### 🟡 Important
1. [§3.4 L877-L898; glossary L121; tests L2304-L2311] — `ReplayCancelled.stream_seq` still has no declared semantics.  
   **Fix:** Insert after the replay-cancellation paragraph:
   > `ReplayCancelled.stream_seq` carries `current_stream_seq` as observed by the daemon at cancel time. It is diagnostic-only: subscribers MUST NOT use it to construct the follow-up subscribe; the follow-up MUST carry `since_fingerprint = None` and route through clause (c).

2. [§3.4 L711-L739] — "pre-v1 schema" still sounds caller-scoped; the discriminator is really `since_boot_id == None` on the envelope.  
   **Fix:** Insert before **Pre-v1 boot_id absence (normative)**:
   > **Definition (normative).** The subscribe envelope carries no explicit version discriminator. For this section, an envelope is **pre-v1 iff `since_boot_id == None`** and **v1+ iff `since_boot_id == Some(_)`**. Classification is per-envelope, not per-caller.

3. [§6 T-31a L2306-L2308 vs Z-29 dense/lock-step retention L945-L951] — T-31a is unreachable unless it is explicitly fault-injected; otherwise the payload buffer cannot evict independently while the index still retains the entry.  
   **Fix:** Replace the first sentence of T-31a with:
   > Fault-inject a transient invariant violation where the delta payload buffer drops a required replay frame before the corresponding replay-index entry is trimmed.

4. [Z-29 boot edge L931-L944] — Boot-edge routing mentions clause (P) even though `ring_oldest_seq` is undefined if the replay index is empty.  
   **Fix:** Replace the Z-29 boot-edge sub-bullet with:
   > - **Z-29 boot edge case.** When `current_stream_seq == 0`, the replay index and delta payload buffer MAY both be empty and `ring_oldest_seq` is undefined. In this regime clauses `(d)`, `(d′)`, and `(P)` MUST NOT consult replay-index membership. Outcomes reduce to: if `since_stream_seq == Some(0)` and boot/fingerprint match (or boot is assumed for pre-v1), emit vacuous `UpToDate { stream_seq: 0 }`; otherwise emit `Resync { snapshot, stream_seq: 0 }`.
