## Findings

### 🔴 Critical
1. [306-470, 1247-1282] Handshake parsing is not fail-closed. `parse_capabilities(...)` has no error branch, so a malformed-but-JSON-valid handshake is neither T-4 fallback nor explicit rejection. **Fix:** replace the direct assignment with an `Ok/Err` match, emit `malformed_handshake`, and stop the cascade on parse failure.
2. [987, 306-560] `run_id` is mandatory in schema but never validated in the read loop. **Fix:** after parse success and before seq validation, reject any `event.run_id != runner.run_id` with `protocol_violation` / `run_id_mismatch`.
3. [1135-1142, 477-560] `unknown_message_kind` is normative, but the algorithm never checks it. **Fix:** insert an explicit closed-set kind gate before runtime dispatch and terminate with `stop_cascade(reason = "unknown_message_kind")`.

### 🟡 Important
1. [2198-2199] The old stale `L1261` ref is gone, but `see §4.2 row` is still ambiguous. **Fix:** `agent deadlocks on first denial (see §4.2 \'accepts_stdin_control\' row [C2], §3.2 handshake reject path, and I-6).`
2. [723-725, 752-757, 1929-1932, 2005-2012] ACP transparency/negotiation is internally inconsistent: pseudocode says “fall back to JSONL”, prose forbids fall-through after ACP identification, and T-6 says stream equality modulo fields while §3.4 says byte-for-byte indistinguishable. **Fix:** make §3.4 say “indistinguishable in shape”, and rewrite spawn negotiation to lock ACP only after a supported ACP identification frame; otherwise remain on JSONL without ever entering ACP.
3. [2008-2012, 1417-1453] T-6 still says `runner_seq` is `reset per Run start`, which muddies the §4.4 rule that it survives RunAttempt boundaries within the same Run. **Fix:** `It is a per-Run monotonic counter — initialized to 0 on the first RunAttempt of a Run and resumed from daemon high-water on subsequent RunAttempts of that same Run — gap-free on the wire, and differs across distinct Runs by construction.`
4. [1514, 1976, 2008] `§4.6.1`, `B14`, and `B15` are referenced but undefined in this document. **Fix:** replace them with live anchors or define them; e.g. `boot_id: Uuid  // same semantics as spec #4 §3.4 SubscribeAck`, `cause = "delta_only_absolute_baseline" (the classifier defined in §4.3)`, and `Per §4.4 post-Ok stamping rule:`.
5. [656-657] `grace_period_ms` is said to be configurable “per-run via handshake”, but §4.2 defines no such handshake field. **Fix:** `grace_period_ms` — per-runner SIGTERM→SIGKILL grace. Default **1000 ms**, configurable per-daemon via config (or explicit spawn-time policy), not via handshake.`
6. [1840-1849] Broker peer auth binds UID + PID lineage, but not process creation time, so PID reuse is still a same-UID spoofing hole. **Fix:** require `(pid, process-start-time)` validation on every accepted peer before MCP traffic.

### 🟢 Suggestions
1. [790-826, 1121] `cross_run_handoff` is reserved-v1 but still treated as a normal queue member/priority class; defer or isolate it to reduce drift.
2. [1247-1282, 1984-1989] Collapse the T-4 fallback story into one canonical paragraph in §4.2 and cross-reference it elsewhere.

## Recommended Actions
1. Fix the three protocol-enforcement gaps first: malformed handshake, run_id mismatch, unknown kind gate.
2. Resolve ACP wording so negotiation, transparency, and tests describe the same contract.
3. Clean up the remaining symbolic/stale references before calling this converged.
