## Findings

### 🔴 Critical
1. [docs/specs/spec-caduceus-orchestrator-algorithm.md:191-208, 1217] — `OrchestratorState` now defines `dispatch_defer_attempts`, but `start_service` never initializes it in the state literal. As written, the pseudocode is internally inconsistent / non-compilable.
   **Fix:** Add `dispatch_defer_attempts: HashMap::new(),` to the `OrchestratorState` initializer in `start_service`.

2. [docs/specs/spec-caduceus-orchestrator-algorithm.md:794-803, 1209-1216, 1471-1481] — The original iter-12 `revalidate_raced` livelock is closed, but a new claimed-run livelock remains when `fetch_by_ids` keeps failing. This branch reschedules forever without incrementing `dispatch_defer_attempts`, releasing `claimed`, or clearing `retry_attempts`; reconcile still cannot see the run because it only inspects `state.running`.
   **Fix:** Bound the `fetch_by_ids` error path too: either increment the same defer counter and abandon at `max_dispatch_defer_attempts`, or explicitly release `claimed`/`retry_attempts` after a configured fetch-failure budget.

### 🟡 Important
1. [docs/specs/spec-caduceus-orchestrator-algorithm.md:725-737, 806-825, 875-899] — Z-9’s abandon branch leaks per-run token maps. `on_retry_timer` only exists after `on_worker_exit` has scheduled a retry from a previously spawned worker, so `token_totals` / `last_reported_tokens` may already exist. The `runs.is_empty()` cleanup path drains them, but the `max_dispatch_defer_attempts` abandon path does not.
   **Fix:** In the `attempts >= state.config.max_dispatch_defer_attempts` branch, also remove `state.token_totals[run_id]` and `state.last_reported_tokens[run_id]`.

2. [docs/specs/spec-caduceus-orchestrator-algorithm.md:1121, 1215-1216] — The field doc says only `on_retry_timer` and `dispatch_run` mutate `dispatch_defer_attempts`, but `on_shutdown` also clears it. The ownership contract is already false in the same spec.
   **Fix:** Update the field comment to include `on_shutdown`, or move the shutdown clear into a documented shared cleanup helper and cite that helper instead.

3. [docs/specs/spec-caduceus-orchestrator-algorithm.md:1758-2025, 869-900, 1121] — No test covers the new Z-9 behavior. The spec has zero test that asserts defer-counter incrementing, reset-on-spawn, threshold abandon, token-map cleanup on abandon, or shutdown clearing of `dispatch_defer_attempts`.
   **Fix:** Add a targeted test that drives a spawned run through repeated retry-time `Deferred` outcomes to the cap, asserts `claimed`/`retry_attempts`/`dispatch_defer_attempts` (and token maps) are cleared at the threshold, and a shutdown variant that proves `dispatch_defer_attempts.clear()` happens.

## Recommended Actions
1. Wire `dispatch_defer_attempts` into `start_service`.
2. Extend the livelock guard to the `fetch_by_ids` error path.
3. Drain token maps on Z-9 abandon.
4. Add one explicit Z-9 regression test and one shutdown-clear assertion.
