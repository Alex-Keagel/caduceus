## Verdict on B21 vs C20

**B21 did not fully resolve C20.**

### Trace
1. `on_worker_exit` removes `state.running[run_id]` at L708-L711.
2. For `ExitReason::Normal` / `Abnormal`, it schedules `Cmd::RetryRun` via `RetryEntry` at L767-L779 and does **not** call `push_finished`.
3. `reconcile_running_runs` only scans `state.running` (L432-L453, L500-L503), so the retry-pending run is now invisible to every §3.2 cascade path.
4. `on_retry_timer` can later classify the fetched run as `Terminal` or `Neither` (L880-L923) and explicitly drain maps without a ring write.
5. Therefore no upstream path in §3.1, §3.2, or §3.4 guarantees a prior `recent_history_ring` write before the retry timer hits `Terminal`/`Neither`.

The explanatory comment at L892-L895 is false for retry-pending runs: the cited cascade sites can only see runs still present in `state.running`.

## Findings

### 🔴 Critical
1. [L880-L923] — `on_retry_timer`'s `Terminal` and `Neither` arms still allow terminal cleanup with no guaranteed `FinishedRunSummary`. `on_worker_exit` already consumed the `RunningEntry`, and §3.2 reconcile cannot see retry-pending runs. The spec therefore still permits a run to disappear from daemon history with no ring write.

   **Fix:** Replace the retry-pending terminalization explanation with:

   ```text
   Retry-pending terminalization (normative). A run that has exited through
   `on_worker_exit`'s `Normal` or `Abnormal` arm is no longer present in
   `state.running`, but it remains logically live via `RetryEntry` until the
   scheduled `Cmd::RetryRun` is resolved. Because `reconcile_running_runs`
   (§3.2) inspects only `state.running`, it cannot guarantee a prior
   `recent_history_ring` write for such a run. Therefore, if `on_retry_timer`
   is the first handler to observe that retry-pending run as `Terminal`,
   `Neither`, or absent from `WorkSource`, `on_retry_timer` MUST perform the
   canonical finalize for that run before draining `claimed`,
   `retry_attempts`, `dispatch_defer_attempts`, `token_totals`, and
   `last_reported_tokens`. This finalize MUST append exactly one
   `FinishedRunSummary` whose `exit_reason` is `ExitReason::DaemonTerminated`
   with cause `WorkSourceTerminal`, `WorkSourceLeftQuery`, or
   `WorkSourceMissing` respectively.
   ```

2. [L1383-L1429] — Ring invariant #1 says the only ring writers are `push_finished` and `terminate_and_finish`, but that writer set cannot satisfy the retry-pending `Terminal`/`Neither` path because the `RunningEntry` was already removed at L708-L711.

   **Fix:** Replace ring invariant #1 with:

   ```text
   Ring invariant #1 (single writer, normative). Only the daemon's main task
   writes to `recent_history_ring` (I-1). The only normative writer sites are:
   (a) `terminate_and_finish`; (b) the defensive `ExitReason::DaemonTerminated`
   arm in `on_worker_exit`; and (c) the retry-pending finalize path in
   `on_retry_timer`, used when `on_worker_exit` has already consumed the
   `RunningEntry` but `on_retry_timer` becomes the first terminal observer.
   Exactly one `FinishedRunSummary` MUST be appended for every terminal
   outcome of a run.
   ```

   **Fix:** Replace the paragraph beginning `token-drain site.` with:

   ```text
   token-drain site. The canonical drain sites are identified by branch name,
   not by line number: `terminate_and_finish` (§3.1); `on_worker_exit`'s
   defensive `DaemonTerminated` arm (§3.5); `on_retry_timer`'s "run vanished
   from WorkSource" branch (§3.5); `on_retry_timer`'s `TrackerClass::Terminal`
   branch (§3.5); `on_retry_timer`'s `TrackerClass::Neither` branch (§3.5);
   and `on_retry_timer`'s dispatch-defer abandon branch (§3.5). These sites do
   not all remove the run from `state.running`: the retry-pending cleanup
   branches run after `on_worker_exit` has already consumed the live
   `RunningEntry`. The common invariant is that each branch drains every per-run
   map it still owns, and any branch that is the first terminal observer MUST
   append exactly one `FinishedRunSummary` before draining token maps.
   ```
