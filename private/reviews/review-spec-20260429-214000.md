## Findings

### 🔴 Critical
1. [docs/specs/spec-caduceus-orchestrator-algorithm.md:707-779, 829-923, 1372-1430, 1441-1455] — **B21 does not fully resolve C20.** `on_worker_exit` removes the `RunningEntry` at lines 708-711, then for `Normal` / `Abnormal` inserts `retry_attempts` and schedules `Cmd::RetryRun` at lines 767-779. `reconcile_running_runs` only inspects `state.running` (lines 432-452), so a retry-pending run is invisible to every §3.2 cascade path. When `on_retry_timer` later classifies `Terminal` or `Neither`, the spec explicitly drains maps without a ring write (lines 881-923). That still allows live maps to be dropped with **no prior `FinishedRunSummary`**.
   **Fix:** Replace the retry-pending finalization contract with:

   ```text
   Retry-pending runs created by `on_worker_exit`'s `Normal` / `Abnormal`
   arms MUST carry a finalize snapshot across the retry window. Add a
   `finalize_snapshot` field to `RetryEntry` containing the consumed
   `RunningEntry` data needed for `FinishedRunSummary`
   (`run_id`, `repo_coordinate`, `attempt`, `restart_count`,
   `started_at`, and the engine-attested `final_tokens` copied from
   `state.last_reported_tokens[run_id]` at exit time).

   When `on_retry_timer` classifies that retry-pending run as
   `TrackerClass::Terminal` or `TrackerClass::Neither`, or when
   `fetch_by_ids([run_id])` returns no row, it MUST append exactly one
   `FinishedRunSummary` before draining `claimed`, `retry_attempts`,
   `dispatch_defer_attempts`, `token_totals`, and
   `last_reported_tokens`. The exit reason MUST be:

   - `ExitReason::DaemonTerminated { cause: WorkSourceTerminal }` for
     `TrackerClass::Terminal`,
   - `ExitReason::DaemonTerminated { cause: WorkSourceLeftQuery }` for
     `TrackerClass::Neither`,
   - `ExitReason::DaemonTerminated { cause: WorkSourceMissing }` when
     `fetch_by_ids([run_id])` returns no row.

   No path may remove retry-pending state without first appending that
   canonical ring entry.
   ```

### 🟡 Important
1. [docs/specs/spec-caduceus-orchestrator-algorithm.md:352-367, 881-895, 909-917] — The prose says retry-pending cleanup is acceptable because some earlier cascade call site already wrote the ring entry, but the actual control flow gives no such guarantee once line 708 has removed the run from `state.running`.
   **Fix:** Replace the paragraph at lines 352-367 with:

   ```text
   If the helper is invoked on a `run_id` that is not in `state.running`
   (early-return at line 298), postconditions 1, 2, 3, 5, 6, and 7 are
   trivially satisfied. Postcondition 4's "no ring write" arm is valid
   only when some prior finalize path has already appended the canonical
   `FinishedRunSummary` for that `run_id`. Retry-pending runs created by
   `on_worker_exit`'s `Normal` / `Abnormal` arms are not in that
   category: those arms remove the `RunningEntry` without writing the
   ring, so any later `on_retry_timer` classification to `Terminal`,
   `Neither`, or "missing from WorkSource" MUST synthesize and append
   the missing `FinishedRunSummary` before draining retry state and
   token maps.
   ```

2. [docs/specs/spec-caduceus-orchestrator-algorithm.md:359-363, 893-895, 973-988, 1426-1427, 2254-2257] — Stale or wrong references remain:
   - `§3.4 cascade call site` is wrong; the cited cascade sites live in **§3.2**.
   - `Ring Invariant #5 (§6)` is wrong; the invariant is defined in **§4**.
   - `L857–866`, `L860–861`, and `L748–752` no longer match the actual drain lines.
   - The drain-site enumeration says each listed site removes the run from `running`, which is false for the vanished/defer branches.
   **Fix:** Replace the drain-site/reference prose with:

   ```text
   The drain sites are: `terminate_and_finish`, the `runs.is_empty()`
   branch in `on_retry_timer`, the dispatch-defer abandon branch in
   `on_retry_timer`, the `DaemonTerminated` defensive-finalize arm in
   `on_worker_exit`, and the `TrackerClass::{Terminal, Neither}` arms in
   `on_retry_timer`. These sites do not all remove the run from
   `state.running`; some act only on retry-pending state after
   `on_worker_exit` has already consumed the `RunningEntry`. Cite these
   sites by function/branch name, not by unstable absolute line number.
   References to ring invariant #5 MUST cite §4.
   ```

3. [docs/specs/spec-caduceus-orchestrator-algorithm.md:1372-1430, 1434-1455] — The ring wording is internally inconsistent. One section says the ring is written on the terminal path of `on_worker_exit`, while another makes the ring the sole source of truth for restart history; daemon-driven terminal paths actually write through `terminate_and_finish`, and retry-pending reclassification currently writes nothing.
   **Fix:** Replace the ring-introduction wording with:

   ```text
   Bounded ring buffer of recently-finalized Runs, owned exclusively by
   the orchestrator main task (Y-4). A `FinishedRunSummary` is appended
   exactly once for each terminal finalize event. The normative finalize
   paths are: (a) `terminate_and_finish`, (b) the defensive
   `DaemonTerminated` arm in `on_worker_exit`, and (c) retry-pending
   reclassification in `on_retry_timer` when that handler is the first
   terminal observer after `on_worker_exit` has already consumed the
   `RunningEntry`. The ring, not any side map, remains the sole source
   of truth for `prior_restart_count`.
   ```

4. [docs/specs/spec-caduceus-orchestrator-algorithm.md:2007-2270] — The tests do not directly cover the retry-pending `Terminal`/`Neither` / missing-row path that triggered C20/B21.
   **Fix:** Add this test text:

   ```markdown
   ### T-10b: Retry-pending reclassification still appends exactly one FinishedRunSummary

   > Exercises: I-4, I-5, ring invariant #1, ring invariant #5.

   **Setup.** Dispatch `R1`, seed `state.last_reported_tokens[R1]` with a
   non-default value, then deliver `on_worker_exit(R1, ExitReason::Normal)`.
   Assert that `state.running` no longer contains `R1` and that
   `state.retry_attempts[R1]` exists. Before the scheduled `Cmd::RetryRun`
   fires, configure `work_source.fetch_by_ids([R1])` to return either:
   (a) `R1` classified as `Terminal`, (b) `R1` classified as `Neither`, or
   (c) no row at all.

   **Expected.**

   1. `on_retry_timer` appends exactly one `FinishedRunSummary` for `R1`
      before removing retry state and token maps.
   2. The appended summary carries the pre-seeded engine-attested
      `final_tokens`.
   3. The exit reason is `DaemonTerminated { WorkSourceTerminal }`,
      `DaemonTerminated { WorkSourceLeftQuery }`, or
      `DaemonTerminated { WorkSourceMissing }` respectively.
   4. A stale retry timer for a superseded token appends no second entry.
   ```
